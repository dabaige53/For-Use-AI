# AI 工作应用笔记

依据本地材料整理日常工作的思路、案例、文字模板和边界。材料中的产品能力只作为工作方法示例，不作为最新事实。

## 1. 先把工作变成信息包

AI 输出质量首先取决于任务信息。工作中的信息不只是正文，还包括目标、背景、角色、流程、数据、约束、示例、历史决策和评价标准。材料越完整、结构越清楚、越贴近使用场景，AI 越容易给出可继续使用的结果。

交给 AI 前，可以先准备一份信息包：

| 项目 | 要回答的问题 |
| --- | --- |
| 目标 | 这次要推动什么判断、行动或交付？ |
| 背景 | 为什么做、给谁看、在什么场景使用？ |
| 材料 | 有哪些文档、表格、记录、数据和事实？ |
| 约束 | 字数、时间、口径、权限和保密边界是什么？ |
| 输出 | 最终要得到摘要、表格、报告、流程说明还是待办清单？ |
| 标准 | 什么结果算准确、相关、完整、可执行？ |

例如，“帮我做活动复盘”可以补成：复盘用于部门例会，目的是判断下一次是否继续投入；活动面向新用户，已知材料包括周期、渠道、预算、曝光、点击、报名、到场、成交和反馈；输出要先列事实，再列原因假设，最后给出三条可执行建议，并标记缺失数据。这样，AI 处理的是一个明确任务，而不是一句需要自行猜测的要求。

非结构化材料也可以先交给 AI 整理，但要指定整理维度和用途。会议纪要可按“背景、结论、分歧、待办、负责人、截止时间、风险”重排；用户反馈可按问题类型、用户身份、频次、影响程度和建议动作分类；复盘材料可按“目标、结果、差异、原因、经验、下一步”组织。

## 2. 理解 AI 当前能看到什么

可以用三个层次理解 AI 的工作：模型训练提供长期形成的通用能力；当前上下文提供本次任务的材料；工具结果提供执行过程中新获得的信息。模型擅长根据已有序列继续生成内容，所以文字流畅、结构完整并不等于事实可靠。当前任务里缺少目标、口径或原始材料时，应先补充信息，避免模型把猜测写成结论。

用户看到的是输入框，系统实际处理的可能是一整包 input：系统规则、用户指令、对话历史、文件内容、当前环境、工具说明、产品规则和权限信息。工具执行后，结果会回到上下文，AI 再判断下一步。由此可以解释同一句提示在不同工作环境中为何效果不同：进入模型的信息、可调用的工具和输出路径不同。

从产品和工作流角度，可用 `Agent Product = Model + Harness` 记忆：Model 负责理解、生成和判断；Harness 是围绕它的工作环境，包含文件、知识、观察结果、动作接口、权限、记忆和执行路径。做工作设计时，要同时问两件事：AI 需要理解什么，以及它可以安全地做什么。

## 3. 用结构化提示词启动协作

提示词不是一次性咒语，而是一份给 AI 的小型任务说明书。可复用的文字模板如下：

```text
Task：我要完成什么任务，结果用于什么决定或行动。
Context：背景、对象、场景、读者、时间和目标。
Content：需要处理的原始材料、数据、文件或已确认事实。
Instructions：请按哪些步骤处理，先做什么，后做什么。
Examples：参考的格式、语气、结构或已有样例。
Output Format：请用什么字段、表格、段落或清单输出。
Review Criteria：请检查事实、口径、逻辑、完整性、风险和可执行性。
``` 

先让 AI 产出初版，再基于结果补信息和改要求。反馈要具体到动作，例如“把结论移到开头”“删除重复表述”“按三个渠道比较成本和转化”“区分已确认事实、原因假设、待补数据和行动建议”“把建议写成负责人、时间和下一步”。“再专业一点”或“再深入一点”无法告诉 AI 该改哪里。

当某些要求反复出现，可以沉淀为 System Prompt、Prompt 文件或项目规则：角色与目标、常用术语、固定输出格式、指标口径、品牌语气、资料位置、可修改范围和必须确认的动作。稳定规则减少重复沟通，但每次任务仍需补充当前材料，不能把规则当成事实来源。

## 4. 把 Agent Loop 迁移到日常工作

适合多数工作的协作循环是：

```text
明确结果 → 读取和整理材料 → 列计划 → 生成初版
→ 调用工具或补充信息 → 人工审查 → 具体反馈 → 迭代交付
```

这个循环可用于报告、文档、分析、流程和自动化。AI 可以负责提取、分类、归纳、起草、重排和比较；人负责定义目标，提供业务语境，判断重要性，确认事实和口径，并决定是否发布或执行。复杂任务可以按角色拆分为调研、撰稿、审稿和风险检查，但最终仍要由一个明确的负责人合并和验收。

遇到低质量输出，可按缺口定位原因：任务不清是定义问题；材料不足是上下文问题；缺少最新或专属资料是检索、文件或工具问题；格式不稳定是示例和输出约束问题；流程无法落地是权限、输入输出或异常处理没有设计清楚。先补最关键的缺口，再要求重写，比不断重复同一句提示更有效。

## 5. 四个可直接迁移的工作案例

### 会议纪要转待办

给 AI 会议记录和参与者信息，要求先提取已确认结论，再识别行动项，补出负责人、截止时间、依赖和风险；信息缺失时标记“待确认”，不要自行补写。输出可分为“结论表、待办表、未决问题、风险”。AI 可以整理和去重，负责人需要确认任务归属、时间和对外承诺，确认后再写入项目工具或发送消息。

### 客户反馈分类日报

```text
触发：收到一批新增客户反馈。
输入：反馈原文、产品模块、已有分类和优先级规则。
步骤：去重 → 分类问题类型 → 提取高频主题 → 标记严重程度
      → 摘要典型案例 → 生成日报。
输出：分类表、高频问题、需要跟进的反馈、待确认项。
审核：高优先级判断、客户原话、敏感内容和外发范围。
沉淀：新增分类规则、典型案例和经确认的优先级口径。
```

### 每周业务周报

先确认统计周期、字段定义和环比口径，再让 AI 读取数据并生成“本周变化、异常指标、已知原因、待补信息、下周行动”。所有数字回到原表核对；原因分为材料已确认和仍待验证；建议要写清动作、负责人或时间条件。发送前由负责人确认重点结论和外发范围。

### 竞品信息整理

先限定竞品范围、比较维度和使用场景，再提供链接、截图、用户反馈或内部记录。让 AI 按“材料中的描述、差异、可能机会、缺失信息”输出，逐项标记来源和判断性质。没有材料支持的内容只能列为待核实假设，不能写成已确认结论。

## 6. 设计工作流时先写清边界

一个可执行的 AI 工作流至少要写清：触发条件、输入、背景规则、处理步骤、判断条件、工具、权限、输出、人工审核点、失败处理和需要沉淀的记忆。每一步都应有明确输入和输出，异常情况要有回退路径。

权限可以分三类：查询、整理、生成等低风险动作可自动执行；修改关键文件、形成重要结论、创建任务或准备外发内容需要确认；删除数据、作出未经授权的承诺或越过保密边界的动作应禁止。工具越多，越要把可见范围、写入范围和确认节点写入规则。

审查至少覆盖：事实是否能回到原始材料，数字和统计口径是否一致，推断是否标明依据，结构是否服务目标，建议是否能执行，格式是否符合交付要求，是否混入敏感信息，外发、删除、承诺等动作是否已获确认。AI 可以先按清单自查，但自查不能代替人的最终判断。

## 7. 沉淀个人 AI 工作系统

从一个高频、重复、边界清楚的任务开始，记录它的标准流程和常见错误。逐步沉淀五类资产：个人 System Prompt、常用任务模板、资料和知识库、可用工具清单、Review Checklist。每完成一次任务，留下有效提示、最终版本、修改原因和新的检查项；下一次只替换当前材料，不必从零开始。

个人系统的目标不是收集大量提示词，而是形成稳定循环：输入材料，生成初稿，人工审查，具体反馈，沉淀模板。能清楚描述最终产物、信息来源、判断标准和权限边界，才是把 AI 用进工作的基础。
