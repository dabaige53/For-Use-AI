# 数据、模型与上下文

本篇以生成文字的大语言模型为主，说明数据、训练与当前输入之间的关系。

## 数据：记录、含义与质量

数据是记录下来的内容，可以是文字、数值、图像、声音或视频。记录可能包含错误、遗漏和主观判断，因此数据不直接等于事实。

理解数据既依赖内容，也依赖结构和产生条件。文字顺序、字段关系、来源、时间范围、单位和定义，都会影响含义。向 AI 提供材料时，应保留理解材料所需的这些信息。

数据有两种作用：训练数据影响模型学到的规律；当前输入影响这次回答的依据。两者都需要关注准确性、完整性和相关性。增加重复、无关或相互冲突的材料，并不必然改善结果。

## 模型：结构、参数与训练

模型通过计算把输入转换为输出。结构规定信息怎样被处理，参数是训练中可以调整的数值。训练依据数据和目标反复调整参数，使输出更符合目标。


文字进入模型，一般经历以下过程：

1. 切分为 Token。Token 可以是字、词的一部分或标点，数量不能直接等同于字数。
2. 将 Token 转为编号，再转成可计算的数值表示。
3. 结合顺序和内容之间的关系进行计算。Transformer 的注意力机制让当前位置结合允许访问的其他位置的信息。



后训练继续调整模型行为。指令训练使用任务与期望回答组成的材料；其他方法还会使用比较、评分或结果反馈。不同模型的方法组合不同。符合偏好、表达清晰与事实准确是不同的评价维度。

## 推理：使用已有参数生成回答

对话时，模型根据当前输入计算后续 Token 的概率，按生成规则选择 Token，再把生成内容作为后续依据。生成规则不一定总取概率最高的一项。


## 上下文：本次实际收到的内容

上下文可能包含当前提示词、被带入的历史、实际提供的资料和应用规则。提示词只是其中一部分。界面显示过的消息和已上传文件，不一定完整进入每次生成。


上下文窗口有容量限制，需要容纳输入并为生成保留空间；具体限制取决于模型和应用。对话增长后，系统可能保留部分历史或压缩为摘要。即使全部放得下，模型也不一定准确使用每个细节。

整理上下文时，保留当前目标、关键事实、有效限制和待解决问题，明确哪一版要求有效，去掉失效或无关部分。未经核实的模型回答不能直接升级为已确认事实。

## 输入与迭代

准备任务时检查六项：

| 项目 | 要说明的问题 |
|---|---|
| 目标 | 要完成什么，最终交付什么？ |
| 背景 | 为什么做，给谁用，必要条件是什么？ |
| 材料 | 依据哪些内容，来源与适用范围是什么？ |
| 要求 | 必须满足什么，有哪些限制？ |
| 输出 | 采用什么形式、篇幅和表达方式？ |
| 标准 | 怎样验收，缺少依据时如何处理？ |

这是检查思路，无需机械套用固定栏目。任务要求与待处理材料应分开表达。复杂任务可以按依赖顺序推进，但各步骤都应服务于最终目标。

收到回答后，先定位问题：方向、依据、遗漏、事实，还是表达。反馈应指出具体位置、修改方向以及需要保留的正确内容。新增要求若替代旧要求，应明确说明；要求冲突时先消除冲突。
