# 对话的输入与输出：三段连续镜头生图提示词

## 讲述范围

核心问题：**用户只发一句话，应用如何组织模型输入、处理模型输出，并让工具结果支持后续调用？**

本地录音仅作为贯穿流程的对象。用户任务为“把这段录音整理成会议纪要”；不展开纪要写法、分类标准、负责人提取或逐句事实核对。最终纪要只作为给人的输出出现。

三个解释镜头，共三张十二格演化板。每张图表现同一镜头的连续状态，不能生成十二张独立主题海报。格数用于展示必要关系与衔接，不对应十二个独立镜头或固定视频时长。

本例是假设应用只向文本模型提供录音位置、再通过转写工具取得文字的教学示例；并非所有模型与应用都这样处理音频。指令、工具和文件位置均为自编示例，不是用户真实文件或某产品隐藏实现。本版替代先前九镜方案，旧文章与旧图片待同步，不作为本版配音、生图依据。本次只修改设计，不启动生图。

## 画面要让观众看懂的三件事

1. **来源与边界：**用户需求、系统指令、环境和工具定义来自不同位置；只有被纳入的内容进入本轮输入。文件位置与文件内容分开。
2. **输出的去向：**模型既可生成给人的回答，也可生成供程序处理的工具请求；请求携带具体工具和参数，但它本身不执行操作。
3. **执行后的循环：**应用执行请求、接收结果、组织下一次输入并再次调用模型。一次用户提问可以经过多次模型调用。

## 固定舞台与模块

用同一幅空间布局贯穿三张板。左侧为用户及信息来源，中间为输入区，第一镜右侧为内容展开区，暂不出现模型；第二镜开始才在右侧显露灰色透视层叠模型；模型右上方通向用户界面，右下方通向外部执行区。宿主程序以薄灰外框包围输入组织、输出分流、工具调度和记录区；模型是独立被调用模块，本地音频在输入框外。

全景不同时展开所有名称和内容：一次只高亮当前关系。局部特写保留低亮位置锚点；拉回时恢复同一舞台，不能交换模型、文件和输入的位置。

| 模块 | 主要图形 | 首次指认文字 | 画面规则 |
|---|---|---|---|
| 用户需求 | 蓝色气泡 | 整理这段录音 | 完整任务由旁白交代；之后保留蓝色气泡 |
| 系统指令 | 绿色短卷页，有三条不模拟可读文字的几何条 | 系统指令 | 与应用侧有明确来源关系，不能从用户气泡发出 |
| 历史 | 后续请求与结果记录 | 历史 | 首次不出现；调用执行后才累积记录 |
| 环境 | 灰白定位标记 | 环境 | 本例主要承载文件位置，不假装已有文件内容 |
| 工具定义 | 空心金色接口，名称位加参数槽 | 工具定义 | 说明结构留在输入侧，不变成执行程序 |
| 本轮输入 | 白色细线开放容器，有不同来源的分组 | 本轮输入 | 分组边界保留；不是所有信息混成系统提示词 |
| 语言模型 | 灰色透视矩形板层 | 语言模型 | 板层和大小不随上下文增加而改变 |
| 输出分流 | 模型外的小分叉节点 | 不必文字标注 | 下路接执行，上路接用户；由应用分派 |
| 实际调用 | 金色实心短票据，带两个字段和菱形甲标签 | 工具调用 | 只在字段特写显示值；甲在参数对象外 |
| 转写程序 | 白色齿轮与扫描窗口 | 转写程序 | 位于模型外，由应用调度 |
| 工具结果 | 白色短胶片，有时间刻度和中性条块 | 工具结果 | 带同形甲标签，时间戳表示结构，不展开原句 |
| 最终回答 | 返回用户界面的白色纸页轮廓 | 会议纪要 | 只有标题与中性段落形状，不展示纪要分类 |

第一镜右侧逐一展开用户需求、系统指令、环境和工具定义的具体教学示例，见本镜指定文字；不展开这些规则怎样制作纪要。工具采用公开 transcribe_audio 定义，原始字段为 file_path、model、language、output_format；具体值为教学示例。时间戳只用00:12、00:25等刻度，无具体讲话内容。

箭头按功能区分：内容传递用短实线箭头，字段对应用无箭头细连线，执行与回填路径只在当前步骤高亮。画面中每条线必须有可辨起终点，不画装饰网络。

## 生图通用提示词

> 生成一张连续科普动画的十二格关键状态分镜板，严格三列四行，每格横向十六比九，整板四比三，细中灰分隔线、窄间隙，阅读顺序左到右逐行向下。最高可用分辨率，保留完整网格。参考核心图的纯黑背景、灰色透视层叠模型、细线几何和留白，不复制参考图的文字、概率图或案例。
>
> 主要内容必须是对象、分组、边界、复制、槽位匹配和方向明确的流动。禁止把画格做成标题加段落的说明卡片。不要在格顶添加解释句、旁白、步骤编号；允许本镜明确指定的短中文标签与右侧输入示例原句；示例是对象的实际内容，不是旁白。全景只有当前焦点附近二至三个标签保持清楚，其他对象靠固定颜色和形状识别。第一镜右侧每次只展开一个来源的示例，最多四行；其余镜头特写最多展开工具名称和一个参数值，不能铺满表格或代码。首格边角可短标“教学示例”。除真实工具 Schema、调用字段与路径外不出现英文、无关文件扩展名、人物、机器人、霓虹或装饰粒子。
>
> 同一对象贯穿全镜，来源被复制后原件保留。模型不自行读取文件、调用系统或修改自身参数。宿主程序通过外围路径组织信息与执行；文件位置进入输入不表示音频已读。不要讲会议纪要怎样分类，不出现“已定事项、行动项、待确认、负责人、预算”等纪要内容。录音与纪要只是任务起点和结果，画面重点是它们之间的输入输出过程。
>
> 每格是一个可辨认的关键状态，不用重影表现整段动作。保持空间连续，只有提示明确要求时改变机位。图形无法独立说明的关系，才用短中文补充；不得把提示词中的解释句自动印进画面。留少量阅读停顿，不能用细碎移动凑格。

使用方式：通用提示词＋对应本镜提示词＋模块身份表。核心参考为[第一期模型图](../../LLM_简要说明/素材/工程素材/images/append.jpg)。相邻板可参考上一张末格的布局，不把上一张网格嵌入新画格。生图时只选择与本镜相关的模块，不能把模块表全文绘入图中。

## 三个关键镜头

### 镜头01｜首次输入与真实工具定义

首次就是首次：没有历史消息。用户需求、应用系统指令、环境与工具定义是四个不同来源。只有后续工具调用和结果才成为对话记录。首次用户本身的消息会被应用保存，但不能虚构此前消息。

本镜参考 ManimGL 的对象组与变换方式：左侧来源标签固定，右侧为正文或代码特写。使用 Write 展开文字，TransformFromCopy 表示加入输入，SurroundingRectangle／Brace 标记字段关系，camera.frame 局部移动与 Restore 保持代码连续。这里只设计可实现的动作，不声称已经渲染 Manim。

布局：平面黑底，左侧四成来源与白色大括号输入组，右侧六成内容；白色中文正文、等宽原始 Schema，语法键名金色，字符串白色，类型青色。去掉玻璃盒、渐变卷页、立体卡片、软件窗口和图标阴影。模型在第二镜才出现。每格不是新幻灯片，沿同一对象的展开、定位与收回演进。

工具原始定义见[核实后的 Schema](../素材/来源/whisper-mcp/transcribe_audio.schema.json)和[固定提交来源](../素材/来源/whisper-mcp/README.md)。英文原字段与描述保留；中文仅作旁注。代码特写是局部视窗，完整 JSON 不挤在每格里。系统指令与示例路径非产品隐藏原文。

**生图提示词：**

> 三列四行十二格，整板四比三，每格十六比九。黑底平面科普动画，细灰分隔线。参考 Manim 与 3Blue1Brown 的排版：固定对象、清晰对齐、细线括号、局部放大、连续变换。首格角标“教学示例”。右侧代码必须遵照给定原始 Schema，不翻译字段，不新增接口字段。逐格如下：
>
> 第1格：黑底平面场景，左侧蓝色“用户”短标签及白色音频波形线，右侧直接书写“把这段本地录音／整理成会议纪要。”不画气泡按钮或软件窗口。
>
> 第2格：用户需求缩为左侧一条蓝色消息行；下方绿色“系统”行选中，细绿色括号连接右侧原句“使用中文，依据取得的资料回答。／需要外部信息时，使用提供的工具。”无纪要分类。
>
> 第3格：绿色指令缩回独立行；灰白“环境”行选中，右侧显示“录音位置”与“/audio/meeting.wav”，旁边波形文件仍在外部。路径是示例，绝不画转写正文。
>
> 第4格：左侧三条输入行用一条大白色左括号归组，旁边标“首次输入”；右侧空白；没有历史行、旧气泡或此前消息。
>
> 第5格：金色“工具定义”行出现，细金色括号指向右侧逐字对齐的等宽代码骨架：{ "name": "transcribe_audio", "inputSchema": { } }。实际排成多行，不是中文属性列表。
>
> 第6格：右侧局部放大原始工具定义的 name 和 description 两项："name": "transcribe_audio", "description": "Transcribe an audio file using Whisper. Supports various audio formats (wav, mp3, m4a, etc.). Returns the transcribed text." 长字符串视觉折行、不可伪造换词；左侧工具行保留。
>
> 第7格：沿同一代码对象向下移动观察窗口，右侧只显示原始嵌套结构 "inputSchema": { "type": "object", "properties": { } }，每层两空格缩进；用细括号高亮 inputSchema，中文侧注“参数结构”。
>
> 第8格：右侧继续放大 properties 中的字段："file_path": { "type": "string", "description": "Absolute path to the audio file to transcribe" }，字符串可视觉折行；只旁注“文件路径”，不把中文写入 Schema。
>
> 第9格：代码观察窗口同时显示 file_path 的 type: string 与外层 "required": ["file_path"]，用一条细金线连接两处 file_path，侧注“必填”；保留 properties 与 required 的不同层级，不把 required 放进 file_path。
>
> 第10格：继续看同一个 properties 下的可选项，展示三个原始结构节选："model": { "type": "string" }, "language": { "type": "string" }, "output_format": { "type": "string", "enum": ["text", "timestamps", "json"] }。右下小标“局部字段”，表示各字段 description 等未在当前特写显示，不假装是完整定义。
>
> 第11格：右侧代码收回到左侧金色工具定义行的副本，原始定义仍在来源区；首次输入的白括号归组四项“用户、系统、环境、工具”，各项保持一条平面文字行，外部波形未进入。
>
> 第12格：同一平面全景落定，四项首次输入在左侧，右侧留空供下一镜显露模型；不画历史、不画模型、不发送工具调用、不输出纪要。
>
> 约束：首次没有历史。全镜不出现模型、执行齿轮或纪要成品。图中代码是可辨识的真实 JSON 结构节选；不能用几条横线或中文卡片代替。说明文字以中文为主，原始字段与描述保留英文。

### 镜头02｜输出不一定是给人的回答

**解释目标：**工具定义被用于形成请求，应用把请求交给程序。

**旁白意图（不印在画内）：**这次模型先输出转写请求。工具名称说明做什么，参数指出处理哪个文件；应用识别请求，再交给执行程序。

**本镜生图提示词：**

> 生成三列四行十二格连续演化板，保持通用舞台与配色。依次表现：
>
> 第1格：承接上一镜左侧完整输入，右侧展开区已收空；镜头拉远，在右侧首次显露灰色语言模型，输入从其左端送入，输出端接宿主分流节点，上路接用户回答位，下路接执行区。
>
> 第2格：镜头局部放大输入侧空心金色工具定义，名称 transcribe_audio，下方长空槽 file_path；只这两项可读，其他模块低亮。
>
> 第3格：输入侧定义原件保持不变，模型右端开始出现新的实心金色请求票据；两者不能直接变形替换，必须保留模型生成环节。
>
> 第4格：请求特写，顶部工具名填入 transcribe_audio，与输入侧同名定义用细无箭头对齐线建立对应；上方用户回答位仍空。
>
> 第5格：请求票据露出与定义同形同位的长参数槽，定义侧的槽旁短标“文本、必填”；两个槽对齐，不加入其他工具。
>
> 第6格：已有环境中的文件位置副本填入实际请求槽，特写只显示"file_path": "/audio/meeting.wav"，来源环境标记保留。
>
> 第7格：从填写的参数向外部录音位置拉一条无箭头对应线，音频波形不移动；表示请求指向哪个文件，不表示已经读取。
>
> 第8格：请求外层贴上菱形“甲”标记，贴近短标“调用标识”；甲位于参数框之外，参数使用 file_path，并补 model: large、language: zh、output_format: timestamps。
>
> 第9格：保持定义与请求的对照作停顿：空心定义提供要求，实心请求携带值。当前焦点只高亮 file_path 槽，不新增说明文字。
>
> 第10格：回全景，金色请求从模型输出端经宿主分流节点转入下方路线；通向用户回答位的上路低亮且为空。
>
> 第11格：金色请求到达白色齿轮旁，短标“转写程序”；应用调度区高亮，录音文件仍在原位，尚无工具结果。
>
> 第12格：执行入口收到带甲请求，参数位置与音频文件的对应关系仍可辨；记录区留请求副本。结束于即将执行的状态，不提前出现纪要。
>
> 全程保持：所有文字仅限指定短标签与必要字段；不新增纪要教学、顶部说明或长段落。原来源保留，路径方向与实际处理顺序一致。

### 镜头03｜执行结果回到输入，回答才继续

**解释目标：**工具结果由应用纳入后续输入，推动下一次模型调用。

**旁白意图（不印在画内）：**程序取得录音并返回转写。应用把请求记录和结果加入下一次输入，再调用模型。最后的纪要才送回用户界面。

**本镜生图提示词：**

> 生成三列四行十二格连续演化板，保持通用舞台与配色。依次表现：
>
> 第1格：承接执行入口的请求甲、白色转写程序与外部录音，上方模型和输入保持低亮，三者位置沿用上一镜。
>
> 第2格：应用调度程序读取指定音频，波形副本沿短线进入扫描窗口，原文件保留。这是第一次实际读取，不从模型画出直接访问文件的手。

> 第4格：结果胶片带相同甲标记离开程序，短标“工具结果”；齿轮停止。结果结构可辨，但不展开正文内容。
>
> 第5格：结果沿底部回程路线到达宿主的收集节点，不直接流入模型；收集区域高亮，其余路径低亮。
>
> 第6格：工具结果的甲与记录中请求甲短暂对齐，配对成功后保持为金色请求、白色结果两个对象；原录音不消失。
>
> 第7格：宿主输入组织区高亮，把请求记录与工具结果副本追加到原输入中。蓝色任务、绿色规则与金色定义都保留，不把整个旧输入重新演一次。
>
> 第8格：局部显示前后两次输入的差别：旧分组低亮，新增的请求记录和结果胶片高亮；仅标“下一次输入”，不显示完整历史文字。

## 验收重点

- 去掉文字后，仍能看出信息从不同来源进入输入、请求向执行区流动、结果回填后再次调用。文字负责认物，不承担整幅图的解释。
- 第一镜的绿色指令来自应用，蓝色任务来自用户；音频文件与文件位置不混同，工具定义不等于正在执行。
- 第二镜的原工具定义始终留在输入侧，模型输出新的请求；请求经应用分流，不直接当作用户答案。
- 第三镜有明确的“执行—收集—组织输入—再次调用”，不能只用工具结果到模型的一根箭头省略应用职责。
