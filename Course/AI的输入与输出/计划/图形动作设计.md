# 图形动作设计

版本：2026-09-16 R1。配合[连续镜头逻辑](本地录音_分镜与生图提示词.md)，内容依据为[正文](../文章/正文.md)。本文件只定义舞台和对象，镜头顺序与旁白由连续镜头逻辑维护。

## 已选视觉基准

用户选定方向 C。后续沿用[镜头01清理版](../素材/图片/视觉基准/镜头01_首次输入_十二格_清理版.png)的不透明黑底、细线图形与局部展开方式；三个主镜头的划分见[当前计划](当前计划.md)。图片中的 Schema 是视觉示意，正式文字依据来源 JSON。

## 为什么上一版丢失图形

失败图第 2—4 格把来源对象缩成文字行，第 5—10 格逐页浏览 JSON，第 11—12 格再回文字列表。观众需要自己记住文件、输入和工具的关系，画面只负责显示术语。旧计划还把工具定义拆成过多字段特写，并要求固定格数，挤掉了执行与回流的解释空间。

这次每段围绕一次关系变化展开：来源汇入、局部展开、生成请求、交给执行、返回新信息。真实内容附着于持续存在的对象，展开是查看对象内部，收回后仍能追踪它。

## 固定舞台

16:9、黑底。坐标以画面左上为 (0%, 0%)。下方 88%—100% 留给字幕。此处尺寸为设计预算，未渲染验收。

- 左侧 5%—24%：来源。蓝色用户消息在上，绿色系统指令在中，灰白环境标记和金色工具接口在下。初始按叙事逐个出现。
- 中左 29%—46%：本次输入。用开放括号归组来源副本，保留颜色、形状和分隔；组装节点位于括号左下。
- 右侧 53%—90%：第一主镜头 的局部展开区，只开一个内容视窗。左侧关系图持续可见；右侧至少保留指向源对象的细连线，不独立成幻灯片。
- 第二主镜头开始：收回视窗，在 (65%, 36%) 首次出现灰色层叠平面模型，输入位置不变。模型右侧 (83%, 36%) 为程序分派节点，上路到 (84%, 14%) 的人类回答位，下路到 (74%, 73%) 的工具执行位。
- 外部录音波形固定在 (17%, 76%)。执行时才沿下方横向路径复制到工具执行位。结果沿底部回到组装节点，再向上进入输入；与音频读取路径分开高度。
- “程序”是组装、分派和调度节点共同的灰色细线联络边界，模型与外部文件各留缺口。它表达职责，不画成软件窗口或强行套住所有对象的盒子。

## 对象身份

| ID | 形状与颜色 | 语义及生命周期 |
|---|---|---|
| U | 蓝色单条消息轮廓，短标“用户” | 首次任务；原件留在来源位，输入使用副本 |
| S | 绿色双行短线，左侧小括号，短标“系统指令” | 应用指令；展开真实教学句，收回同一轮廓 |
| E | 灰白定位点连一段路径线，短标“环境” | 文件位置；指向 A 的无箭头细线只表对应 |
| D | 金色开放接口，主槽长、其余三槽短，短标“工具定义” | 工具参数结构；主槽 file_path，其余槽对应三个可选字段 |
| I | 白色开放大括号，内部四项有间隔 | 本次输入；不是聊天窗口、文件容器或固定 API 格式 |
| A | 白色波形与短底线，短标“本地录音” | 文件本体；仅解释文件位置或执行读取时出现，其余阶段收起，收起不表示删除文件 |
| M | 三至五层灰色平面轮廓，标“语言模型” | 第二主镜头才出现；同一模型两次调用，大小与层数不变 |
| C | 金色单线请求轮廓，参数槽已有值，短标“工具请求” | M 输出的新对象；D 原件保留，不直接变成 C |
| X | 白色输入口—扫描竖线—输出口，标“转写程序” | 模型外的执行程序；运动仅在执行期间发生 |
| R | 青白色短横线组，左侧两枚时间刻度，标“转写结果” | 本例假设成功返回的文字；不是原始音频或最终纪要 |
| H | 白色单页轮廓，短标“会议纪要” | 第二次 M 输出，交给人阅读，不表示已写文件或发送他人 |

颜色之外同时依靠位置、轮廓和短标签识别。S、R 都可能含短线，但来源、颜色和时间刻度不同。文件路径保留在 E；不能把 A 的波形复制进第一次 I。

## 动作语法

| 动作 | 可见变化 | 解释含义 |
|---|---|---|
| 复制 | 原对象保留，副本沿实线箭头移动 | 内容被纳入或传递；不表示文件被搬走 |
| 局部展开 | 源轮廓保留为锚点，连接线通向右侧放大内容 | 查看同一对象的内容；结束后缩回原槽 |
| 无箭头连线 | 两端同时轻亮 | 字段对应、路径指向；不表示执行或数据传输 |
| 括号聚合 | 分项副本进入同一个开放括号 | 程序组织本次上下文；来源边界仍可辨 |
| 模型生成 | 输入先到达 M，随后输出端出现新对象 | 输出根据输入生成；不是从定义直接复制出调用 |
| 分派 | C 向下，H 向上，经同一程序节点 | 程序处理请求或把回答呈现给人 |
| 回流 | R 先到程序，与 C 对应，再进入 I | 工具结果要经过组织才能用于下一次模型调用 |

后续 Manim 可用 TransformFromCopy 表达副本、save_state/Restore 表达展开还原、Brace 表达分组；生成用新对象出现，避免用 Transform 暗示 D 自己成为 C。现阶段没有实现这些动画。

## 文字预算与图形验收

全景每个对象保留短标签；旁白句不重复印满屏幕。局部展开占画面不超过约四成宽，只显示正在解释的字段和必要父层级。Schema 可以分两个焦点查看，但不能逐个字段再分镜。非焦点对象降低亮度，轮廓和连线仍可辨。

遮住长句和字段值，仍应能追踪 U/S/E/D → I → M → C → X → R → I → M → H。读回文字后，应能回答路径从哪来、哪个槽必填、程序处理哪个文件。这两项都满足，才算图文共同解释了机制。
