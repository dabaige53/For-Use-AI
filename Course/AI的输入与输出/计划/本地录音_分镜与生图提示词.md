# 本地录音生成会议纪要：模块与连续分镜生图提示词

## 本版范围

用户任务：**“把这段本地录音整理成会议纪要。”**

九个解释镜头。每张图表现一个镜头的大部分演化，按行连续阅读；格子是关键状态，不是独立镜头，也不是等时长截图。先展开具体内容，再收成短标签和图形，最后总结全程。本版只交付提示词，不生成图片。

本例的录音、转写、系统指令、工具定义、请求及结果全部是互相对应的教学示例，不是对用户真实文件的读取，也不代表某产品的隐藏提示词或真实接口。未指定助手产品；不采用笔记软件界面。本例选择外部转写工具，不据此声称所有模型都不能直接接收音频。

旧文章使用“读取现有纪要”案例，尚未同步此次改编；当前镜头的内容依据为下列完整示例。正文与阅读页更新前，不将旧稿交给配音或生图。旧二十镜头方案停止作为当前入口，已有图片仅为旧试稿。

## 一、完整示例：内容先成立，再设计动画

### 用户与环境

- 用户消息：把这段本地录音整理成会议纪要。
- 附件显示名：项目讨论录音。
- 应用解析后的示例文件位置：本地录音／项目讨论音频。这是中文示意路径，不是可执行文件路径。
- 初始输入：有任务与文件位置，没有音频转写正文。
- 执行范围：应用运行环境可以读取这个指定文件。图中的路径并不等于权限；权限由执行环境落实。

### 应用提供的系统指令示例

> 你负责依据会议材料整理纪要。使用中文。区分已决定事项与讨论中的建议。未明确的负责人、日期或结论标为待确认，不自行补齐。工具失败时说明未取得的资料。

画面分次展开“依据会议材料”“区分决定与建议”“未明确则待确认”，不把整段指令同时铺满每格。全文用于设计核对，不能只保留三个口号而丢掉其完整含义。

### 其他上下文：来源与功能各自分开

| 模块 | 本例具体内容 | 来源及作用 | 是否主线展开 |
|---|---|---|---|
| 项目约定 | 纪要按“已定事项、行动项、待确认”组织，条目保留来源时间 | 应用选入的项目文档；约定输出组织方式，不自动等于系统角色 | 是 |
| 历史消息 | 上一轮用户说：“这是试点项目的讨论。” | 此前用户消息；提供主题，不是新录音事实 | 是，短暂展开 |
| 保存偏好 | “纪要简短。” | 可选长期偏好；本轮未单独加载，图中不连入输入 | 仅作为边界对照 |
| 环境 | 当前文件位置：本地录音／项目讨论音频 | 应用提供的任务状态；定位操作对象 | 是 |
| 技能说明 | 整理方法文档 | 可按需提供，本例不加载 | 仅作为边界对照 |
| 工具定义 | 下列“转写录音”工具 | 应用提供的接口说明，帮助模型构造请求 | 是，重点 |

不把模块画成每个产品都固定存在的必备列表。消息角色与来源类型不是同一维度；画面按来源分组只是教学展示，不宣称真实请求必然以这个顺序排列。

### 工具定义：参数结构的中文展开

| 部分 | 完整示例 |
|---|---|
| 名称 | 转写录音 |
| 用途 | 读取指定音频，返回带时间戳的转写段落 |
| 参数整体 | 对象；对象中包含以下命名字段 |
| 音频位置 | 文本类型，必填；说明为可读取的音频文件位置 |
| 包含时间戳 | 布尔类型，可选，默认开启；含义为每段文字附开始时间 |
| 结果约定 | 成功时返回分段转写；失败时返回错误信息 |

“用途和参数定义”“结果约定”“真正执行程序”是三个有关联但不同的对象。结果约定不是请求参数；调用标识也不是工具参数槽中的一项。中文字段用于讲解结构，并非可直接提交的接口代码。

### 第一次模型输出：给程序的请求

| 外层字段 | 值 |
|---|---|
| 输出类型 | 工具调用 |
| 调用标识 | 请求甲 |
| 工具名称 | 转写录音 |
| 参数／音频位置 | 本地录音／项目讨论音频 |
| 参数／包含时间戳 | 开启 |

本例实际显式填写“开启”，虽然工具默认也开启。模型生成请求，应用接收并调度；模型尚未取得录音内容。“请求甲”是用于结果配对的教学标签，不解释为模型必须亲自生成的某种真实接口编号。

### 执行结果：进入后续输入的新材料

- 对应调用：请求甲。
- 状态：成功。
- 源文件：本地录音／项目讨论音频。
- 以下四段仅是短教学录音的完整转写示例，不是长会录音的全量还原。

| 时间戳 | 转写原句 | 后续用途 |
|---|---|---|
| 00:12 | 试点就定九月二十一日开始。 | 已定事项及明确日期 |
| 00:25 | 小林负责整理试点名单。 | 行动项及明确负责人 |
| 00:39 | 名单什么时候交，我们下次再定。 | 行动项截止日期待确认 |
| 00:52 | 预算还没批，先不要按批准写。 | 预算审批状态待确认 |

转写可能有识别误差。时间戳提供回听定位，不保证转写正确。本例成功主线假设这四句已正确转写；正式制作如使用真实录音，应核对原音。

### 第二次模型输出：给人的纪要

> **试点项目会议纪要**
>
> 已定事项：试点于九月二十一日开始。〔00:12〕
>
> 行动项：小林整理试点名单；截止日期待确认。〔00:25、00:39〕
>
> 待确认：预算尚未批准。〔00:52〕

主题来自历史消息，三条纪要的事实来自转写；结构来自项目约定；“不补齐日期与结论”受系统指令约束。图中的对应线是供观众核对依据，不声称显示模型的隐藏思考或精确内部因果。不写回文件、不发送给参会人；用户只要求整理。

## 二、图形模块与视觉语法

### 宿主程序：负责连接模型和环境

吸收[原文核心与采纳说明](../../../资料库/02-知识与原文/AI输入输出与智能体/输入输出核心与课程采纳.md)后，增加一个贯穿全片的薄灰宿主外框，边角短标“宿主程序”。它包含输入组织、工具调度、输出分流和记录存储；语言模型作为被调用的独立模块嵌在其中，不能与宿主混成一个对象。

宿主底部的细线记录库保留消息、请求、结果；本轮输入只是从中选出的工作信息。外框从镜头02起逐步显露，布局一旦建立就固定；特写可收成小型位置锚点。仅当组织输入、执行工具或继续调用发生时，高亮对应区域，其余区域低亮或暂不展开。镜头05首次显露输出分流节点，镜头07首次显露循环调度节点，镜头09仅回看。程序职责用节点和路线呈现，不增加长解释卡片。

### 固定舞台

全景时左侧约四分之一为用户与来源，中间约三分之一为本轮输入，右侧为灰色透视层叠语言模型。外部执行区放在下方，和模型之间用足够间距与一条细虚线边界分开。局部展开时放大当前对象，保留一个低对比的全景锚点；不把完整总览缩成无法看清的小字。

模型输入端在左、输出端在右。请求从输出端沿下行路线到应用执行区；工具结果沿底部返回输入组织区，下一次输入才从左端再次进入模型。路线不得穿过无关模块。最终纪要从模型右侧朝上方用户可见区展开，区别于朝下的程序请求。

### 对象身份

| 对象 | 图形主体 | 文字用法 | 保持不变的关系 |
|---|---|---|---|
| 用户任务 | 蓝色气泡 | 首次显示完整需求，以后收成“用户任务” | 原消息保留 |
| 本地录音 | 白色文件轮廓内有波形，附一条播放时间轴 | 名称与位置分次显示 | 波形始终对应同一文件，原件不消失 |
| 系统指令 | 绿色卷页，三段规则有独立定位点 | 一次只展开一条规则 | 来源标签“应用提供”不与用户气泡合并 |
| 项目约定 | 紫色文件夹，三个栏目轮廓 | 栏目名称首次出现，之后保留形状 | 表示组织方式，不提供录音事实 |
| 历史 | 灰蓝色旧气泡 | 只展开本例一句历史 | 与当前用户任务有时间先后 |
| 环境 | 灰白定位标记连接录音位置条 | 位置文本仅在匹配时放大 | 位置不表示已读到内容 |
| 工具定义 | 金色接口外框，内含可展开参数槽 | 参数名、类型、必填标记 | 空心说明与实心请求有形状区别 |
| 调用请求 | 金色实心窄票据，外层带菱形“甲”标签 | 工具名与具体参数在特写中展开 | “甲”属于外层调用标识，不混入参数 |
| 执行程序 | 白色齿轮与转写波形扫描窗 | 首次标“转写程序” | 在模型外；由请求触发 |
| 工具结果 | 白色分段胶片，左边保留时间戳刻度 | 逐段显示原句，不塞成一页密文 | 结果带相同菱形“甲”，原音保留 |
| 最终纪要 | 白色开放纸页，青色实线确定项、琥珀虚线未定项 | 显示短纪要正文与来源时间 | 未定项不能变成确定状态 |

### 工具定义与请求的跨镜匹配

镜头04、05使用同一套槽位布局：顶部为工具名称，中部为两行参数，底部之外留调用标识位置。第一行音频位置是长文本槽，第二行时间戳是双位置开关。工具定义保留空心轮廓与类型、必填提示；实际请求沿用相同尺寸和顺序，以实心填充值区分。

定义不会变成或消失于请求：在模型输入侧保留原定义，输出侧生成按其结构填写的新请求。类型匹配线只是解释字段对应，不代表模型没有生成过程。镜头04不填具体文件位置，留给镜头05完成这一步。

### 动作的含义

- 揭开界面后层：说明用户没输入但应用会提供的内容。
- 从源对象复制到输入：说明被纳入本次调用；源对象不搬走。
- 放大参数槽、类型尺与必填缺口：说明接口结构，而不是展示装饰卡片。
- 将具体值嵌入相符的槽：说明请求怎样使用工具定义。
- 同形“甲”标签贴合：说明请求和结果配对，不代表权限认证。
- 播放头沿波形前进、对应文字段落展开：说明音频转写过程；抽样关键状态不承诺真实处理速度。
- 原句连向纪要条目：说明可核对的内容依据，不是模型内部思想路径。
- 缩回全景：把已解释的具体对象收成短标签；缩略前先让观众读懂。

## 三、每次生图使用的通用提示词

> 生成一张解释型动画的连续演化分镜板，严格遵循本镜指定网格。三列三行用于九格，三列四行用于十二格；每格横向十六比九，画格等大，细灰色分隔线，窄间距，从左到右逐行连续。整板分别为十六比九或四比三。采用最高可用分辨率，保证完整格子和中文清晰。参考指定核心图的纯黑背景、灰色透视层叠模型、细线几何和克制留白，只参考视觉，不复制参考图文字或案例。
>
> 图形为主：通过波形、时间轴、参数槽、边界、复制、路径和对齐解释内容。文字只包括本镜指定的中文任务、规则、字段、原句及短标签；不把分镜描述或旁白印到每格上方，不增加标题横幅、整段解释、英文、代码、格号或水印。首格边角可有小字“教学示例”。同一焦点最多展开三行主要文字，其他模块收拢或降低对比。不同概念不用同样的大矩形卡片填满画面。
>
> 逐格绘制关键状态；各格可以用于机制变化、内容对照或必要阅读停顿。停顿格保持对象原位，只改变观察焦点，不伪造新内容；不以小幅淡入、平移凑格数。九格、十二格是当前排版，后续可以按解释需要减格并重排。保持对象身份、配色、来源、模型板层和先后顺序。原始文件、指令和消息被复制后仍保留。除指定镜头变化外保持机位稳定。所有箭头都有具体起点终点；请求和结果不可逆向、不可越过必要步骤。不画模型直接操作硬盘，不将工具定义画成已经执行，不表现输入更新改变模型参数。不画机器人、装饰网络、霓虹、粒子雨或脑内思考。

提交组合：通用提示词＋本镜提示词＋本镜所需的完整示例字段。无需把所有模块全文都塞进每镜。上传核心参考图 `Course/LLM_简要说明/素材/工程素材/images/append.jpg`；相邻镜可增加上一板作为对象连续性参考，但只承接末格，不把上一张网格嵌进新格。

文字很多的特写如无法清晰生成，拆为同镜的前后两张板，保留重叠衔接状态；不要缩小所有字体或删掉关键字段。不得用“画面更复杂”作为增加格数的理由。

## 四、逐镜设计与生图提示词

### 镜头01｜从本地录音到用户任务

**解释问题：**用户给了目标和文件位置，不等于模型已经听过录音。

**画面主体：**波形文件与需求气泡；不开场展示长流程图。

**首尾衔接：**用户指定录音，发送后露出输入边界。

**本镜生图提示词：**

> 生成同一镜头的9格连续演化分镜板，三列三行。保持通用视觉和对象身份。以下格号只用于指示顺序，不印在图片中。
>
> 第1格：左侧白色录音文件内绘一段波形，下方短名“项目讨论录音”；右侧留黑，文件保持完整。
>
> 第2格：文件上方展开蓝色用户气泡，完整文字“把这段本地录音整理成会议纪要”，气泡尾部指向用户侧，不指向文件。
>
> 第3格：气泡发送，镜头拉远，中央白色细线围出“本轮输入”，右边低亮灰色层叠“语言模型”；录音仍在左下。
>
> 第4格：从用户气泡复制任务至输入区，原气泡不消失；输入内暂用短标签“用户任务”，录音波形没有进入。
>
> 第5格：局部放大文件底部位置标记，展开“本地录音／项目讨论音频”，位置与文件用短线关联。
>
> 第6格：仅复制位置标记进入输入，原录音与原位置保留在外部；通过空心位置标记与实心波形区别地址和内容。
>
> 第7格：输入区特写，任务与位置并列；留一个空的时间轴轮廓，旁边短标签“转写未取得”，不得虚构转写句子。
>
> 第8格：左右对照：左边真实波形轮廓在输入框外，右边输入内只有位置标记，用边界凸显差别，不画跨界读取箭头。
>
> 第9格：回全景，气泡、外部录音、仅含需求与位置的输入、模型同框；在输入上方留空间，承接下一镜展开应用提供的信息。
>
> 全程约束：录音正文未进入输入；“转写未取得”是当前状态，不是声称模型永远不能接收音频。

**验收重点：**录音正文未进入输入；“转写未取得”是当前状态，不是声称模型永远不能接收音频。

### 镜头02｜系统提示词的内容与注入

**解释问题：**应用提供什么规则，它们怎样成为输入的一部分？

**画面主体：**规则原句与对应约束同框，内容讲清后一次归入输入；保留一格阅读停顿。

**首尾衔接：**接上一镜，在用户界面后方揭露应用指令。

**本镜生图提示词：**

> 生成同一镜头的9格连续演化分镜板，三列三行。保持通用视觉和对象身份。以下格号只用于指示顺序，不印在图片中。
>
> 第1格：承接已有用户任务和文件位置；应用界面后层直接展开绿色“系统提示词”，来源标“应用提供”，宿主外框的输入组织区域首次显露。
>
> 第2格：放大“依据会议材料”，旁边录音波形与空纪要之间保留一个来源定位缺口；文字解释要求，图形强调尚待取得依据，不填本例事实。
>
> 第3格：切换“区分决定与建议”，将两个同形事项标记分置实线与虚线边界，分别短标“决定”“建议”；规则与分类方式同框，不生成实际纪要。
>
> 第4格：切换“未明确则待确认”，空负责人槽和日期槽保留空缺，琥珀虚线标签“待确认”贴近空槽；不得自动补人名或日期。
>
> 第5格：保持上一格规则与空槽作阅读停顿，只把观察焦点从负责人移到日期；对象不移动，不新增文字，让观众看清“空缺被保留”。
>
> 第6格：展开其余要求：“使用中文”对应中文栏目轮廓；“工具失败时说明未取得资料”对应断开结果路径。两组上下分开，前面主要规则收为低亮定位点。
>
> 第7格：回到总览，宿主的输入组织区域高亮；绿色规则副本一次进入本轮输入，应用侧原指令保留，用户任务与文件位置不被覆盖。
>

> 第2格：只点亮最初蓝色任务和白色录音位置，旁边应用提供的绿色规则、紫色约定、灰蓝历史、金色工具定义保持可辨。
>
> 第3格：这些已纳入的模块在本轮输入中被一个细括号圈起，箭头指向第一次模型调用，外部录音仍与输入分开。
>
> 第4格：仅高亮已存在的宿主输出分流节点与向下执行路线，原金色请求保持原位；局部重显“转写录音”和位置两个已知字段，短标签“给程序：提出操作”。不生成新请求。
>
> 第5格：路径继续点亮执行程序和波形读取，原纪要不动；短标签“程序执行”，不再产生第二份音频副本。
>
> 第6格：仅高亮已存在的“甲”结果、收集节点和回填路径，下一次输入中的四个时间刻度亮起；所有对象留在完成位置，短标签“带回依据”。
>
> 第7格：仅高亮已存在的第二次调用、宿主分流节点和上方纪要路线，短标签“给人：说明结果”；保持最终纪要原位，不再生成或发送一次。
>
> 第8格：并排放大金色请求与白色纪要两个输出局部，前者有工具、参数、调用标识；后者有纪要和来源时间，不用两段长文比较。
>
> 第9格：回全景稳定结束，只有三个短提示贴近对应区域：“输入包含什么”“输出交给谁”“执行带回什么”；用户任务在左，纪要在右，底部工具循环完整。
>
> 全程约束：本例只有一次工具调用、两次模型调用。不要凑百分比衡量工具贡献，也不把程序输出叫作隐藏思考。

**验收重点：**本例只有一次工具调用、两次模型调用。不要凑百分比衡量工具贡献，也不把程序输出叫作隐藏思考。

## 五、交付与验收

本版共九个解释镜头、九十三个分镜状态（含阅读停顿）：五张九格板与四张十二格板。系统提示词镜由十二格收为九格，减少重复出现、收拢和移动。镜头数由解释问题决定，分镜状态数量不直接决定成片时长。实际旁白和动画停留时间在后续试读中确定。

逐张验收：

1. 图形变化是否解释关系，而非把几段文字摆成海报；去掉额外旁白横幅后，来源、类型、路径和对应关系仍可辨。
2. 是否先展示具体内容，再收成短标签；不能从头到尾只有“系统”“工具”两个词和抽象方块。
3. 请求中的文件位置是否始终对应同一本地录音；“请求甲”是否只用于配对这次请求和结果。
4. 转写是否由外部程序执行；成功结果是否先回到后续输入；模型是否始终没有直接操作硬盘。
5. 四句转写、四个时间戳、纪要日期及小林姓名是否一致；截止日期和预算是否保持未确认。
6. 画面是否区别给人的纪要与给程序的调用；不能把第一次输出画成已完成的纪要。
7. 文字是否准确可读，没有编造内容、英文泄漏和格间跳变。规则、参数和转写只在各自特写展开。
8. 上一镜末态与下一镜首态是否承接；局部放大不代表重新加载或重新执行。镜头04与05的参数槽是否同形同位；镜头06是否保持中性转写，到镜头08才分类。
9. 宿主是否按“收集结果—组织输入—再次调用”依次高亮；镜头09只回看已存在的节点，不能新增模块或重跑操作。

可选旁支只在后续确有需要时增加：文件不可读、转写失败、含糊语句需回听、长音频分段读取。失败分支必须返回失败结果，不能继续用本例成功转写。当前不生成这些旁支，也不加入笔记检索、自动保存或消息发送。
