# 任务执行与证据核验

一份报告最容易获得信任的时刻，往往恰好也是最需要警惕的时刻：版式工整、段落清晰、论点明确，结论看起来像是经过了严谨的定量分析。我们顺着流畅的文字读下去，很难察觉出其中某一项推论是在哪一个环节悄然偏离事实的。

应对这种隐蔽风险，最有效的工作方法是：**先别急着让 AI 写出成文报告，让它先交出结论成立之前的那张证据表。**

本文用完整的 12 条培训反馈，手把手走一遍从原始记录到可信报告的全流程。文中的材料、分类与输出均为用于教学复算的示例，读者可以独立核对每一步的逻辑链路。

## 先决定这份报告要改变什么

假设你负责组织复盘，要在下一次培训筹备会上提出两项优先改进建议。你需要的是一页简短、有据可查的讨论材料，说明“建议改什么、依据何在、还有哪些未知条件”。这次任务不需要长篇大论的总结，更不应演变成一个复杂的全景汇报。

你手里的原始材料只有以下 12 条反馈：

| ID | 原始反馈内容 |
| --- | --- |
| F01 | 后排听不清讲师的声音。 |
| F02 | 实操时间太短，还没做完就结束了。 |
| F03 | 麦克风中途断了两次。 |
| F04 | 案例很贴近工作，希望增加练习。 |
| F05 | 开始前找教室花了十分钟。 |
| F06 | 讲得太快，操作步骤没跟上。 |
| F07 | 投影上的字太小，后排看不清。 |
| F08 | 发的资料很有用，希望提前一天收到。 |
| F09 | 声音清楚，但演示切换得太快。 |
| F10 | 希望保留答疑，今天的问题没来得及问。 |
| F11 | 练习有帮助，但希望给更多完成时间。 |
| F12 | 整体不错，没有其他建议。 |

[下载这组原始反馈 CSV](案例/活动反馈.csv)。

观察这份材料，首先要确立数据边界：每条记录有唯一编号，但**没有记录学员姓名、总出勤人数、满意度评分或预算**。这意味着：我们只能按“记录条数”进行统计，既不能把 12 条记录等同于 12 位独立学员，也不能外推全场的整体满意度。

在此约束下，任务指令可以写得极具穿透力：

> 仅依据这 12 条反馈，为下次培训的筹备会提出两项优先改进建议。
> 
> 请先输出包含 ID 与原始文本的逐条分类表，允许一条记录归入多个主题；按记录条数统计，不得推算人数或满意度。
> 
> 分类经人工核对确认后，再撰写一页决策报告，将事实、解释、建议与未知条件清晰分开。

要求先看中间表格，并非增加繁琐手续。报告的所有高级结论均建立在底层分类之上；分类是整条推理链中最容易出现语义漂移的地方。在表格形态下发现偏差只需改一行，一旦错误被写进三个论述段落，修正的成本将成倍放大。

## 分类判断与数字统计，是两项独立的工作

在处理语义分类时，计算机往往按关键词匹配，而人类理解依赖上下文关系。

以 F09（“声音清楚，但演示切换得太快”）为例：若仅凭关键词“声音”将其粗暴划入“声音问题”，就会直接污染统计结果。这说明：**程序能够分毫不差地数出某个标签出现了几次，却无法仅凭计数准确性来担保归类本身的合理性。**

人工确立严格的业务口径后，我们得到如下归类表：

| 类别 | 对应记录编号 | 记录条数 |
| :--- | :--- | :---: |
| **声音问题** | F01、F03 | 2 |
| **练习与节奏** | F02、F04、F06、F09、F11 | 5 |
| **场地指引** | F05 | 1 |
| **画面可读性** | F07 | 1 |
| **资料发放时间** | F08 | 1 |
| **答疑安排** | F10 | 1 |
| **无具体改进建议** | F12 | 1 |

在这个示例中，每条记录恰好对应一个核心主题，累计为 12。在允许多标签的复杂任务中，各类别计数之和完全可以大于总记录数。无论哪种情况，都必须核查 12 个编号是否全部被覆盖，严禁为了强求合计平衡而擅自删去某条记录中的次要诉求。

先核查文本归类，再校验汇总数字，才能确保最终产出的报告不是“基于错误前提的完美计算”。

## 从事实到建议，需要补上业务判断

从分类表中的“练习与节奏有 5 条记录”，能直接得出“绝大多数学员对授课非常不满”吗？

显然不能。首先，5 条在 12 条中并未过半；更关键的是，F04 表示“案例贴近工作，希望增加练习”，F11 表示“练习有帮助，但希望给更多时间”。它们表达的是对实操价值的认可与深化诉求，绝不能被等同为负面差评。

客观严谨的事实陈述应当是：

> 在收到的 12 条反馈中，“练习与节奏”是记录最多的改进主题（共 5 条）；其中包括对演示速度过快的意见，也包括肯定实操价值后提出的延长练习时长诉求。

这种表述没有夸张的情绪渲染，却具备高度的真实性与可用性。它守住了原始材料允许表达的强度，没有为了让结论显得“有深度”而人为制造矛盾。

![原始反馈编号经过分类和解释形成结论，再为建议提供依据](配图/05-evidence-chain.svg)

*图 2：从客观事实到行动建议，必须补上人类对现实影响与执行成本的权衡。出现频次高，不自动等于必须优先解决。*

进一步看，为什么两项建议选择“练习节奏”和“声音检查”，而不是出现频次并列第三的其他项目？
- **练习与节奏（5 条）**：频次最高，且直接关乎核心技能的掌握；
- **声音问题（2 条）**：虽然只有 2 条，但后排听不清、麦克风中断会直接摧毁听课体验。课前进行后排试听与设备联调，行动成本极低，却能防范重大体验事故。

这个决策过程清楚地表明：**数据本身不会自动生成决策优先级。** 将事实转化为建议，需要引入对“影响面”和“实施代价”的综合权衡。这一推导逻辑应当在报告中透明呈现，而不是假装成某种纯数学的必然推论。

## 交付一页可落地的决策报告

完成前置的归类、核对与推导后，最终的成文报告只需精炼地呈现决策所需的核心要素：

> ### 下一次培训优先改进建议
> 
> **说明**：本建议依据 12 条课后反馈分析整理。统计单位为记录条数，不可推算独立学员人数或全场满意度。
> 
> **建议一：优先重构讲解与实操的时间配比。**
> - **事实依据**：F02、F04、F06、F09、F11 共 5 条记录涉及练习时间不足、增练诉求或演示过快，是本次最集中的改进主题。
> - **候选行动**：在不延长总课时的前提下，建议压缩部分单向讲授，为关键操作的步骤确认留出充裕时间，方案待讲师确认可行性。
> 
> **建议二：建立课前音频与后排视听检查机制。**
> - **事实依据**：F01 提到后排听不清，F03 提到麦克风中途断音。
> - **候选行动**：开课前 15 分钟在教室后排进行试听联调。目前尚无证据表明需要采购新设备，首要任务是排查现有设备链路与环境遮挡。
> 
> **附注事项**：F05（指引）、F07（投影字号）、F08（课件提前发放）、F10（保留答疑）已归入后续备忘清单。最终改进方案需结合场地日程与组织预算进一步核定。

这份报告之所以能够让人放心交付，是因为附带了原始数据 CSV 与明确的分类依据。任何参会者对结论有疑问，都可以直接顺着编号回溯到具体记录，而无需盲目信任起草者的修辞口吻。
