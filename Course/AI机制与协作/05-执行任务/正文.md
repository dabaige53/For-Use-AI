# 别急着要报告，先让 AI 交出证据

一份报告最容易获得信任的时刻，可能恰好也是最需要警惕的时刻：段落已经排好，结论很明确，建议也写得像是经过了充分分析。我们顺着文字往下读，却不容易看见某个判断是从哪一步开始偏离材料的。

换一种做法：先别让 AI 写报告，让它交出结论成立之前的那张表。

本文用一组完整的培训反馈走一遍这个过程。活动、12 条记录、错误分类和最终报告均为作者构造的教学示例，不是某个模型的实际运行评测。它的价值不在于演示 AI 成功了多少次，而在于读者能够自行核对每一步。

## 先决定这份报告要改变什么

假设下次培训的筹备会只能优先推动两项改进，我们需要一页讨论材料，说明建议做什么、依据是什么、还有哪些条件未确认。这次不需要全面展示活动成绩，也不必立即建设一个分析系统。

手里的材料只有下面 12 条反馈。每条有唯一编号，但没有参加者身份、总人数、满意度评分和预算。也就是说，我们能统计记录，不能据此统计独立人数，更不能算出整体满意度。

| ID | 原始反馈 |
| --- | --- |
| F01 | 后排听不清讲师的声音。 |
| F02 | 实操时间太短，还没做完就结束了。 |
| F03 | 麦克风中途断了两次。 |
| F04 | 案例很贴近工作，希望增加练习。 |
| F05 | 开始前找教室花了十分钟。 |
| F06 | 讲得太快，操作步骤没跟上。 |
| F07 | 投影上的字太小，后排看不清。 |
| F08 | 发的资料很有用，希望提前一天收到。 |
| F09 | 声音清楚，但演示切换得太快。 |
| F10 | 希望保留答疑，今天的问题没来得及问。 |
| F11 | 练习有帮助，但希望给更多完成时间。 |
| F12 | 整体不错，没有其他建议。 |

[下载这组原始反馈 CSV](案例/活动反馈.csv)。后续分类可以增加标签，但不应悄悄改写原文；删重、合并和措辞修正，都会影响解释，需要单独说明。

现在，任务可以表达得很具体：

> 仅依据这 12 条反馈，为下次培训提出两项优先改进。先给出保留 ID 与原文的逐条分类，一条记录允许多个标签。按记录统计，不当作人数，不推算满意度。分类核对后再写一页报告，把事实、解释、建议和未知条件分开。

先看中间结果，并不是为了给简单任务增添手续。这里的结论依赖分类，分类就是最值得提前检查的环节。等到错误被写进三个段落、一张图表和一份摘要，再修正它反而更费力。

## 一个“但”字，为什么会改变统计结果

看看 F09：“声音清楚，但演示切换得太快。”

假设分类表把它放进“声音问题”，你会接受吗？关键词确实出现了，意思却相反。它肯定声音，提出的问题是演示节奏。把它归错，不只是一行表格不好看，还会让后面的声音问题数量增加，练习与节奏数量减少。

我们可以据此规定：“声音问题”只纳入听不清、声音中断等负面反馈；“练习与节奏”纳入练习时间、增练需求、讲解和切换速度。按这套口径，得到如下汇总：

| 类别 | 对应记录 | 条数 |
| --- | --- | ---: |
| 声音问题 | F01、F03 | 2 |
| 练习与节奏 | F02、F04、F06、F09、F11 | 5 |
| 场地指引 | F05 | 1 |
| 画面可读性 | F07 | 1 |
| 资料发放时间 | F08 | 1 |
| 答疑安排 | F10 | 1 |
| 无具体改进建议 | F12 | 1 |

这个例子中，每条恰好归入一个主题，所以合计为 12。允许多标签时，类别计数之和可以超过记录数；此时应另外检查唯一 ID 是否全部覆盖，不能为了让合计等于 12，强行删去某条意见中的第二个问题。

这里也能看出，分类判断与数字计算是两项工作。程序可以正确数出某个标签有几条，却不能仅凭计数正确就证明标签合理。先看原文支持什么分类，再核对汇总，才不会得到一份“算得完全正确，但统计对象已经错了”的报告。

## 五条记录，离“大多数人不满意”有多远

“练习与节奏有 5 条相关记录”，是按当前口径可以复算的结果。把它写成“大多数参加者不满意”，却越过了几道没有证据的推断。

我们不知道有多少位参加者，不知道一人是否提交过多条，也没有整体满意度数据。即便暂时假设每条来自不同的人，5/12 也不到一半。更重要的是，F04 说案例贴近工作，希望增加练习；F11 肯定练习有帮助，希望有更多完成时间。它们包含改进需求，却不能都改写成否定评价。

更准确的结论是：

> 在这 12 条反馈中，练习与节奏是记录最多的改进主题，共 5 条；其中既有节奏过快的意见，也有在肯定练习价值之后提出的增练需求。

这句话少了一点冲击力，多了一点可用性。它保留了材料允许表达的强度，不会因为要写出“有洞察”的报告，就把温和的建议升级为严重的不满。

## 出现最多的问题，就一定最先解决吗

既然练习与节奏有 5 条相关记录，优先检查讲解与操作时间的分配，是有理由的。但第二项为什么考虑声音，而不是另外某个类别？

不是因为两条记录证明了设备一定有问题，更不是因为数量可以自动生成优先级。声音问题可能直接影响能否听懂内容，课前进行后排试听和设备检查，是一种范围较小、值得讨论的候选行动。这一步已经包含对影响与实施负担的判断，应该明确写出来。

同样，5 条练习与节奏反馈，也不能直接推出“延长一小时”。我们还不知道实际课时与可调整空间。更谨慎的建议，是先拟一版不增加总时长的分配方案，看看能否缩短部分讲解，给练习完成和步骤确认留出时间。

建议可以超出对原文的复述，但不能假装自己已经拥有未提供的预算、根因和执行条件。它应该是有依据的下一步，而不是披着事实外衣的猜测。

## 让报告短下来，但让依据留下来

有了前面的工作，一页报告反而容易写了。它不必重复全部过程，只需要把读者作决定所需的信息放在一起。

> **下一次培训的两项优先改进建议**
>
> 本报告依据 12 条虚构教学反馈，统计单位为记录，不能推断独立参加者人数或整体满意度。
>
> **优先调整练习与讲解节奏。** F02、F04、F06、F09、F11 共 5 条记录涉及练习时间、增练需求或演示速度，是当前分类中最多的改进主题。建议先拟一版不增加总时长的分配方案，为练习完成与步骤确认留出时间，再由讲师核对可行性。
>
> **课前检查音频覆盖。** F01 提到后排听不清，F03 提到麦克风中断。建议在实际教室进行后排试听和设备检查。现有记录不足以确定根因，也不能证明需要采购新设备。
>
> F05、F07、F08、F10 涉及指引、投影可读性、资料发放和答疑，保留为后续检查项。F12 没有提出具体改进建议。两项优先级仍需结合实际课时、场地条件与组织者判断确认。

这份报告可以进入筹备会，但不代表改进已经执行。与报告一起留下原始 CSV 和分类口径，下一位读者才有机会复查数字，而不是只能相信上一位作者的语气。

## 知道在哪里检查，也要知道在哪里结束

交付前，检查可以直接围绕这次任务展开：12 个编号是否都被覆盖，有没有新增或改写原文；分类是否符合口径，计数是否对应编号；报告有没有把记录说成人数，把建议写成定论，把未知条件偷偷补成事实。

这些条件满足以后，本轮就可以结束。继续增加封面、动态图表和自动化流程，未必能让筹备会更容易作出选择。如果接下来的问题是“怎样在既有课时里增加练习”，那就需要补充时间表，开始一个输入更明确的新任务。

从一张分类表到一页报告，这个过程没有追求让 AI 显得无所不能。它只是把容易混在一起的工作拆开：先理解记录，再汇总事实，最后解释为什么采取某项行动。

**可信的报告，不是没有人能够质疑的报告，而是有人提出疑问时，我们知道应该回到哪里。**
