# 任务执行与证据核验

一份报告最容易获得信任的时刻，往往恰好也是最需要警惕的时刻：版式工整、段落清晰、论点明确，结论看起来像是经过了严谨的定量分析。我们顺着流畅的文字读下去，很难察觉出其中某一项推论是在哪一个环节悄然偏离事实的。

应对这种风险，可以先调整工作顺序：**先别急着让 AI 写出成文报告，让它先交出结论成立之前的那张证据表。**

本文用完整的 12 条培训反馈，走一遍从原始记录到可核查报告的流程。文中的材料、分类与输出均为用于教学复算的示例，读者可以独立核对每一步的逻辑链路。

## 先决定这份报告要改变什么

假设你负责组织复盘，要在下一次培训筹备会上提出两项优先改进建议。你需要的是一页简短、有据可查的讨论材料，说明“建议改什么、依据何在、还有哪些未知条件”。这次任务不需要长篇大论的总结，更不应演变成一个复杂的全景汇报。

你手里的原始材料只有以下 12 条反馈：

| ID | 原始反馈内容 |
| --- | --- |
| F01 | 后排听不清讲师的声音。 |
| F02 | 实操时间太短，还没做完就结束了。 |
| F03 | 麦克风中途断了两次。 |
| F04 | 案例很贴近工作，希望增加练习。 |
| F05 | 开始前找教室花了十分钟。 |
| F06 | 讲得太快，操作步骤没跟上。 |
| F07 | 投影上的字太小，后排看不清。 |
| F08 | 发的资料很有用，希望提前一天收到。 |
| F09 | 声音清楚，但演示切换得太快。 |
| F10 | 希望保留答疑，今天的问题没来得及问。 |
| F11 | 练习有帮助，但希望给更多完成时间。 |
| F12 | 整体不错，没有其他建议。 |

[下载这组原始反馈 CSV](案例/活动反馈.csv)。

观察这份材料，首先要确立数据边界：每条记录有唯一编号，但**没有记录学员姓名、总出勤人数、满意度评分或预算**。这意味着：我们只能按“记录条数”进行统计，既不能把 12 条记录等同于 12 位独立学员，也不能外推全场的整体满意度。

根据这些边界，可以这样提出任务：

> 仅依据这 12 条反馈，为下次培训的筹备会提出两项优先改进建议。
> 
> 请保留原始全文表，再输出包含 ID、分类与简短归类依据的逐条分类表，允许一条记录归入多个主题；按记录条数统计，不得推算人数或满意度。
> 
> 分类经人工核对确认后，再撰写一页决策报告，将事实、解释、建议与未知条件清晰分开。

先看中间表格，是为了尽早检查影响结论的分类依据。表格中一条记录归错，可能只需修改一行；如果已经据此写出多个段落，就还要检查相关计数、解释和建议。

## 分类判断与数字统计，是两项独立的工作

分类需要读懂上下文，模型和人工判断都可能出错，不能只凭关键词归类。

以 F09（“声音清楚，但演示切换得太快”）为例：它肯定了声音，批评的是演示切换速度。如果看到“声音”就归入声音问题，统计结果就会偏离原意。**标签数得对，不代表标签分得对。**

按每条记录表达的具体改进诉求，可以逐条核对如下分类：

| ID | 分类 | 简短归类依据 |
| --- | --- | --- |
| F01 | 声音问题 | 后排听不清讲师声音。 |
| F02 | 练习与节奏 | 实操未完成，希望有更多时间。 |
| F03 | 声音问题 | 麦克风中途断音。 |
| F04 | 练习与节奏 | 肯定案例，提出增加练习。 |
| F05 | 场地指引 | 找教室耗时。 |
| F06 | 练习与节奏 | 讲解太快，操作跟不上。 |
| F07 | 画面可读性 | 投影字号小，后排看不清。 |
| F08 | 资料发放时间 | 肯定资料，希望提前一天收到。 |
| F09 | 练习与节奏 | 肯定声音，批评演示切换太快。 |
| F10 | 答疑安排 | 问题没来得及问，希望保留答疑。 |
| F11 | 练习与节奏 | 肯定练习，希望增加完成时间。 |
| F12 | 无具体改进建议 | 仅有总体肯定，没有具体建议。 |

再按类别汇总记录条数：

| 类别 | 对应记录编号 | 记录条数 |
| :--- | :--- | :---: |
| **声音问题** | F01、F03 | 2 |
| **练习与节奏** | F02、F04、F06、F09、F11 | 5 |
| **场地指引** | F05 | 1 |
| **画面可读性** | F07 | 1 |
| **资料发放时间** | F08 | 1 |
| **答疑安排** | F10 | 1 |
| **无具体改进建议** | F12 | 1 |

在这个示例中，每条记录恰好对应一个核心主题，累计为 12。在允许多标签的复杂任务中，各类别计数之和完全可以大于总记录数。无论哪种情况，都必须核查 12 个编号是否全部被覆盖，严禁为了强求合计平衡而擅自删去某条记录中的次要诉求。

先核查文本归类，再校验汇总数字，可以避免只顾计数、忽略分类依据。

## 从事实到建议，需要补上业务判断

从分类表中的“练习与节奏有 5 条记录”，能直接得出“绝大多数学员对授课非常不满”吗？

显然不能。首先，5 条在 12 条中并未过半；更关键的是，F04 表示“案例贴近工作，希望增加练习”，F11 表示“练习有帮助，但希望给更多时间”。它们认可实操价值，同时提出了改进诉求，不宜一概归为负面差评。

更贴近材料的表述是：

> 在收到的 12 条反馈中，“练习与节奏”是记录最多的改进主题（共 5 条）；其中包括对演示速度过快的意见，也包括肯定实操价值后提出的延长练习时长诉求。

这种表述保留了意见之间的区别，也没有超出材料能支持的范围。

![原始反馈编号经过分类和解释形成结论，再为建议提供依据](配图/05-evidence-chain.svg)

*图 2：从客观事实到行动建议，必须补上人类对现实影响与执行成本的权衡。出现频次高，不自动等于必须优先解决。*

进一步看，为什么可以把“练习节奏”和“声音检查”作为两项优先建议，供筹备会讨论？
- **练习与节奏（5 条）**：频次最高，涉及跟上操作、完成练习所需的时间；
- **声音问题（2 条）**：后排听不清、麦克风中断会妨碍接收讲解内容，因此可以优先考虑课前后排试听与设备检查。但故障原因、影响范围和检查成本仍需核实，不能仅凭这两条反馈认定方案一定可行。

这个决策过程清楚地表明：**数据本身不会自动生成决策优先级。** 将事实转化为建议，需要引入对“影响面”和“实施代价”的综合权衡。这一推导逻辑应当在报告中透明呈现，而不是假装成某种纯数学的必然推论。

## 形成一页供决策使用的报告

完成前置的归类、核对与推导后，最终的成文报告只需精炼地呈现决策所需的核心要素：

> ### 下一次培训优先改进建议
> 
> **说明**：本建议依据 12 条课后反馈分析整理。统计单位为记录条数，不可推算独立学员人数或全场满意度。
> 
> **建议一：优先调整讲解与实操的时间配比。**
> - **事实依据**：F02、F04、F06、F09、F11 共 5 条记录涉及练习时间不足、增练诉求或演示过快，是本次最集中的改进主题。
> - **候选行动**：在不延长总课时的前提下，建议压缩部分单向讲授，为关键操作的步骤确认留出充裕时间，方案待讲师确认可行性。
> 
> **建议二：建立课前音频与后排视听检查机制。**
> - **事实依据**：F01 提到后排听不清，F03 提到麦克风中途断音。
> - **候选行动**：考虑开课前 15 分钟在教室后排进行试听联调。这是待确认的候选安排，并非已验证的时间标准，需确认场地开放时间、人员与设备条件。目前尚无证据表明需要采购新设备，先排查现有设备链路及现场环境，再判断故障原因和处理成本。
> 
> **其他待安排事项**：F05（指引）、F07（投影字号）、F08（课件提前发放）、F10（保留答疑）也需要讨论如何安排。最终改进方案需结合场地日程与组织预算进一步核定。

交付时，应把原始数据 CSV 和逐条分类依据一并提供，让参会者能顺着编号回到具体记录。保存报告后，还要确认文件可以打开，正文、分类表和汇总表中的数字与编号一致，所附材料可以访问。

这些核对让报告更容易检查，并不保证结论一定正确。两项建议仍供筹备会选择，是否采用，要结合现场信息和实际资源判断。
