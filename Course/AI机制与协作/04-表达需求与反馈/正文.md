# 需求表达与反馈闭环

“你得先想得一清二楚，AI 才能帮你把事情做好。”这句话看似正确，却常常成为很多人使用 AI 的心理包袱。在现实工作中，许多任务恰恰是在看到初稿、比对过不同方案之后，我们才逐渐明确自己到底需要什么。

真正需要警惕的，不是带着模糊的想法起步，而是在模糊尚未消除时，误把顺眼的草稿当成最终成品。

**任何输入给 AI 的内容，都会造成概率地形的改变。**
系统内置的提示词、应用注入的规则、历史对话的残留，以及你在输入框里写下的每一个字，都在共同重塑模型当下的条件概率分布。例如，系统内置指令若偏向“资深专业”，或者你在需求里随手写了“炫酷、有科技感”，就会在地形上迅速砸出一个强引力的侧沟。这是因为在预训练海量语料中，这些词汇天然与繁杂的前端工程脚手架、抽象学术黑话存在极高的统计共现概率。模型在自回归生成时顺着坡度滑落，输出就会不可遏制地偏航。

面对偏航，单纯催促“重新写”并不能填平深沟。想要拿到预期结果，关键在于看清每一次输入是如何改变地形的，并运用具体的手段主动修正与优化这些生成走向。

下面通过 5 个典型场景，对比原始策略与调整策略的生成轨迹与对话变化，看清需求表达与反馈调整的关键手法。

---

## 显式配平：用交付约束压平过度工程

当你在需求里提出“炫酷、有科技感”等形容词时，模型往往会默认连带拉出一整套复杂的工程依赖与脚手架。在输入中显式补上使用者的现实能力与交付形态，保留视觉期望的同时施加约束，就能有效压制过度工程的冲动。

| **User**：写一个炫酷、有现代科技感的番茄钟网页。<br><br>**AI**：为你规划现代化前端方案，引入 React、Tailwind CSS 和 Framer Motion 动效库。请先在终端执行以下安装步骤：<br>`npx create-react-app tomato-clock`<br>`npm install framer-motion tailwindcss`<br>完成环境配置后，再开始编写组件……（导致用户因本地环境问题无法完成交付） | **User**：我是小白，简单点。一个双击可用的 HTML 文件即可。<br><br>**AI**：已生成单个 HTML 文件，内置完整 CSS 样式与 JavaScript 倒计时逻辑，下载保存后直接双击文件即可在浏览器运行使用。 |

**落地要点**：分析业务材料时，不要泛泛要求“全面分析”，而是给出“用于筹备会选优先级、仅依据现有材料、先归类不写长文”的具体约束，防止生成空话套话。

## 特征解耦：拆解纠缠的多重维度

要求方案“严谨”时，模型在激活严密逻辑的同时，往往会连带激活学术黑话与论文式的空洞模板。解决这种纠缠的关键，是把复合的要求拆解成若干条互不干扰的白话验收维度。

| 原始策略（滑入黑话堆砌） | 调整策略（拆解独立验收） |
| :--- | :--- |
| ![特征解耦 原始策略](配图/04-terrain-entangle-a.gif) | ![特征解耦 调整策略](配图/04-terrain-entangle-b.gif) |
| **User**：以严谨的架构标准设计一个用户注册接口。<br><br>**AI**：基于 DDD 领域驱动设计标准，划分为表现层、应用层、领域层和基础设施层。引入 CQRS 读写分离架构、防腐层适配器及事件溯源模式，生成 500 行接口规范模板与论文式说明……（过于庞杂抽象，业务代码难以直接落地） | **User**：设计用户注册接口，分别验收：字段边界清晰、表达直白、代码直接可用。<br><br>**AI**：直接交付清晰方案：<br>1. 字段定义：明确参数类型与必填项（username 3-20位字符，password 须含字母数字）；<br>2. 校验规范：给出参数格式检查逻辑与标准 JSON 错误码；<br>3. 附带直接可运行的接口处理函数实现代码。 |

**落地要点**：提出严肃技术方案时，把“严谨架构”拆成三条白话规则：边界清晰、表达直白、开箱即用。

## 给出样例：一行示例胜过多段说明

多段抽象的格式规定与排版要求，模型分别解析时容易遗漏细节。直接给出包含输入、管道与输出的一两行真实示例，能最快帮模型建立清晰的格式认知。

| 原始策略（弱线索容易遗漏） | 调整策略（示例锁定范式） |
| :--- | :--- |
| ![给出样例 原始策略](配图/04-terrain-case-better-a.gif) | ![给出样例 调整策略](配图/04-terrain-case-better-b.gif) |
| **User**：这是 Linux 环境。用 shell 列出文件详情，再从输出中过滤目标内容。<br><br>**AI**：在 Linux 中查看文件可以使用 `ls` 命令，参数 `-l` 用于显示详细信息。如果要过滤文本，可以使用 `grep` 工具或者写一段 shell 脚本将文件详情重定向写入临时文件，再逐行读取匹配……（说明冗长繁琐，遗漏了管道符的核心用法） | **User**：这是 Linux 环境，参考示例 `ls -al \| grep`，列出文件详情并过滤出 `.log` 日志文件。<br><br>**AI**：直接使用管道符一行完成：<br>`ls -al \| grep "\.log$"`<br>该命令会列出当前目录下的全部详细信息，并通过管道直接过滤输出以 `.log` 结尾的日志文件。 |

**落地要点**：规范输出结构时，与其写三段排版禁令，不如在输入中直接贴出包含 1~2 行示例的表格模板（编号、摘要、归类、动作）。

## 语义重锚：将旁支线索重新降级为证据

排查问题深入时，局部的报错信息会被反复强化，模型的注意力很容易被带偏，甚至把排查某个细枝末节当成了新任务。此时必须明确主任务边界，将旁支线索重新降级为参考证据。

| :--- | :--- |
| ![语义重锚 原始策略](配图/04-terrain-drift-a.gif) | ![语义重锚 调整策略](配图/04-terrain-drift-b.gif) |
| **User**：根分区满了，请找出原因并释放磁盘空间。<br><br>**AI**：排查日志发现存在大量 SSL 证书过期与 DNS 解析报错，正在逐步检查证书链与域名解析配置……（注意力被报错吸引，彻底偏离了清盘任务） | **User**：当前唯一目标是清理磁盘。SSL 报错只作为日志暴增的证据，请立即定位大文件并释放磁盘空间。<br><br>**AI**：排查发现正是因为 SSL 频繁报错，导致应用日志产生数千万条报错记录，单文件膨胀至 82 GB 占满根分区。已提供日志轮转与清空方案，执行后成功释放 82 GB 磁盘空间。 |

**落地要点**：面对分类或归纳偏差，不要空泛催促“仔细看”，而是明确说明因果关系、限定修改范围，重锚核心目标。

## 会话重开：提纯术语后开启纯净会话

在多轮探索中，各种试错、推翻和修改意见会留在上下文历史里。如果直接在旧对话中推进最终交付，模型容易受到早期废弃指令的干扰。先在探索中提炼出准确定型的核心词，随后开启纯净新会话，能极大提升最终交付质量。

| **User**：（在经历数十轮尝试、纠错与反悔的旧对话中）按刚才讨论的，把官网样式定稿。<br><br>**AI**：受到前文大量废弃方案与冲突修改意见干扰，生成的代码同时混杂了早期浅色卡片与后期深色主题，布局结构混乱，难以直接落地交付……（旧会话历史严重污染上下文） | **User**：（开启全新纯净会话）设计官网首页，采用 Linear 设计美学与 Bento Box 网格布局，深色主题，发光微边框与半透明卡片。<br><br>**AI**：在新会话中精确对齐风格要求，直接交付一套纯正的深色 Linear + Bento Box 风格官网首页代码，结构清晰无冗余。 |

**落地要点**：定稿切忌在包含几十轮沟通、纠错的长会话中滚雪球。探索敲定标准后，新建纯净会话，带入冻结口径一次性完成交付。

## 需求与反馈要点一览

| 核心困境 | 应对策略 | 发生机理 | 协作手法 |
| :--- | :--- | :--- | :--- |
| **过度工程** | **显式配平** | 模糊大词激活复杂工程依赖 | 补充使用者现实条件与交付形态，施加约束压制发散 |
| **黑话堆砌** | **特征解耦** | 严肃大词连带激活空洞术语 | 拆解正交独立的白话验收维度，切断术语链条 |
| **执行偏航** | **给出样例** | 抽象文字说明容易被忽略 | 给出单行高密度代码或表格样例，直接锁定范式 |
| **规则漂移** | **语义重锚** | 局部报错导致注意力跑偏 | 及时截断偏离，将旁支降级为证据，重申核心目标 |
| **越改越乱** | **会话重开** | 早期探索在上下文留下干扰 | 提炼出核心定论后，新开纯净会话，轻装完成定稿 |

把每一次输入与反馈看作是对模型生成路径的主动引导，善用配平、解耦、样例、重锚与会话重开，就能摆脱“改了又改、越改越乱”的怪圈，稳步拿到高质量的交付成果。
