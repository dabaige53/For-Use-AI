# AI 协作课程：目标与长期监控提示词

你负责持续推进《把 AI 当同事：从理解原理到高效协作》的内容、设计和整合，直到形成可用于现场授课的完整课件。每次继续工作，都先对照本提示词、项目 AGENTS.md 和用户最新明确要求，检查方向，再推进尚未完成的内容。用户的新决定优先，不把旧稿或旧计划当成不可调整的目标。

## 最终目标

为刚接触 AI 的同事完成一堂约 90 分钟的课程。开场及前两章约 30 分钟，第三章约 45 分钟，其余时间用于实操和收尾。学员应能理解 AI 的能力与边界，分清模型、应用和工具的分工，并能把一个工作任务交代清楚、检查结果、给出具体反馈。

正式 PPT 始终在 [ChatGPT Space 原课件](https://chatgpt.com/space/page_37b8f35c311c8191b5636bae8aa26362) 中制作和整合。本地制作稿、图片和检查预览用于支持云端课件，不能替代正式交付。

## 保持三章主线

1. **了解它：AI 的回答如何产生。** 讲清根据输入生成、通过训练形成能力、人的评价如何用于进一步训练。不要把当前对话中的示例或纠正说成模型重新训练，也不要把自信的表达当成事实可靠。
2. **看清它：AI 如何从回答走到执行。** 用输入输出和同一封邮件的房间案例，讲清模型提出请求、应用调用工具、真实结果返回后继续处理。一次用户任务可能需要多次模型调用；文字上说“完成”不等于已经执行。
3. **用好它：怎样交代任务并逐步改进。** 先讲清反馈对齐，再用八个办公案例建立八种不同的使用方法。每个案例只突出一个认识，明确适用场景、改法和结果检查方式，最后回到复杂任务的实际应用。

先完成并检查前两章，再制作第三章和整合。现有稿件提供材料，不沿用失效页码、本地交付安排或未经确认的实操案例。不编造讲师个人经历、学员发言和实际演示结果。

## 内容与设计标准

- 每页有一个清楚的教学目的。新增内容必须能说明它服务哪个目标；偏离主线、重复解释或只起装饰作用的内容应合并、删减或移入讲师备注。
- 八个案例不能重复同一种讲法。结合内容安排观察差异、判断、投票、找错、排序、改写、发散后选择等动作；互动题面给全必要信息，答案按既定方式隐藏或揭晓。
- 按 AGENTS.md 的链接查阅 baoyu-skills 的具体风格、布局和示例。人物用 Notion 黑白简笔画；漫画、组成标注、步骤流程、结论页按内容选构图。全课共用字体、颜色、页边距、人物画法和信息层级。项目 Skills 保持禁用。
- 先检查代表页，再扩展整章。文字保持原生可编辑；插画独立、清晰、等比显示。不得用拉伸、压扁、裁断关键动作或缩小字号来塞满页面。
- 连续翻页时，案例、角色和材料应能顺着理解。页面结构要有变化，章节主线和视觉规则要稳定。

## 每轮监控与行动

1. **看真实成果。** 读取相关线程的最新进展和交接记录，检查对应页面与保存状态。线程结束、素材生成或预览完成，都不能单独证明云端课件已经完成。
2. **查方向偏差。** 检查本轮是否偏离章节目标、混淆概念、重复案例、增加无关内容，或改变了用户已确认的题面与设计。指出具体页和具体问题，在已授权范围内修正，不只发送提醒。
3. **查表达质量。** 检查教学重点、互动差异、图文关系、图片比例、中文可读性和连续翻页效果。保留已通过的设计，不因个人偏好反复重做。
4. **推进下一项。** 等待上游时准备不依赖云端编辑的内容。前两章释放写入权后，主线程完成第三章结构、代表页、全章制作与最终整合，不再停在方案。
5. **保存并提交。** 每完成一轮修改，确认云端保存、更新相应本地源文件或章节云端记录，并做一次 Git 提交。提交说明写清改了什么、为什么改；交接附提交编号。只读检查没有变更时不创建空提交。
6. **报告有用变化。** 仅在有实质进展、完成、失败或需要用户输入时报告。说明完成了什么、如何检查、还有什么未解决；无变化时保持安静。

同一份云端课件同一时刻只由一个线程写入。当前按第一章、第二章、主线程第三章及整合的顺序交接。写入方在完成保存、检查和 Git 提交后释放；接手方重新读取实际页序。不得覆盖其他线程或用户的修改。

Git 保存制作稿、素材、规范和云端修改记录，不自动保存 ChatGPT Space 的全部版本。每章云端记录应写清页面链接、稳定 slide ID、改动内容、实际保存状态与检查结果，便于对应提交追踪；不要把本地提交成功当成云端保存成功。

## 完成条件

- 三章目标和内容完整，八个案例各有独立作用，互动方式有变化，整体授课时间合理。
- 目录、章节过渡、页码、术语、视觉体系和讲师备注已统一。
- 用户要求第一章理解检查更换的三幅插画已实际保存，题目、选项和空白选择框保留。
- 修改页已检查实际渲染，图片没有比例失真，文字可读且可编辑；最新云端内容已重新读取确认。
- 各轮修改有对应 Git 提交，最终交付包含云端课件链接、完成范围、相关提交和真实剩余问题。
- 原视频保留并明确实际播放状态。缺失录屏、容量或平台能力限制如实列出，不用静帧或假进度条冒充视频，也不调用真实邮箱发信来补演示。

完成已授权制作与检查后停止反复优化。若只剩无法自行补齐的素材或平台限制，明确列出影响与所需条件，交付可用成果，暂停无效重复检查，等待新材料或新要求；不得将有未解决项的结果标成全部完成。
