## M002 · assistant

如果你的培训内容本身已经很“重”——大量视频、网页交互、3D 地形、四象限图、画布——那么 UI 反而不应该继续强调视觉表现。最适合的方向不是“炫酷大屏”，而是：

**极简编辑型演示界面 + 沉浸式内容舞台。**

我会建议你把整个 HTML 培训设计成接近 **Apple Keynote × Linear × Notion × 数据叙事网页** 的感觉，而不是传统 PPT。

核心原则可以概括成一句话：

> UI 退到背景，内容成为舞台中心；只有在需要操作时，界面才出现。

你可以采用这样的视觉体系。

整体背景以暖白或非常浅的灰为主，例如 `#F7F7F5`、`#FAFAFA`，不要纯白到刺眼，也尽量避免大面积渐变。正文使用接近黑色的 `#171717`，辅助文字 `#737373`，边框使用非常淡的 `#E8E8E8`。

颜色控制得非常严格。全套培训最好只保留：

- 黑 / 白 / 灰作为 UI 基础色
- 1 个品牌强调色
- 数据图表必要时再增加 2–4 个功能性色

否则视频、地图、数据图本身已经会产生很多颜色，页面会很容易失控。

字体建议走现代无衬线体系，比如 Inter、SF Pro、Geist、IBM Plex Sans，中文可以使用苹方、思源黑体或者 MiSans。标题不要做得特别巨大，HTML 培训和 PPT 最大的区别就是：你不需要每一页都像海报。

例如一张典型页面可以是：

```text
AI 如何改变信息处理方式                         03 / 12

不是更快地完成任务，
而是重新设计人与信息之间的关系。

────────────────────────────────────────

                [ Interactive Canvas ]

          点击任意节点查看信息流转过程

────────────────────────────────────────

关键发现
传统流程：人 → 工具 → 数据
AI 流程：人 → Agent → 工具 / 数据 / 模型
```

这种页面非常适合培训，因为讲师在讲，人眼关注的始终是一个中心。

你可以把页面分成 4 种基本模板，而不是每页重新设计。

第一种是「Narrative Slide」，用于讲观点。

左边大概 35%，放标题、结论和一两句话；右边 65% 放图、视频或演示。

```text
┌──────────────────────────────────────────┐
│ 01  从 Chat 到 Agent                     │
│                                          │
│ ChatGPT 改变的不是搜索，                 │
│ 而是软件的交互模式。                     │
│                                          │
│ 一句话说明                               │
│                                          │
│                      [动态图 / 视频]      │
│                                          │
└──────────────────────────────────────────┘
```

这是你整个培训里最应该大量使用的模板。

第二种是「Stage」，也就是全屏舞台。

特别适合：

- 视频
- 3D 地形
- 网页 Demo
- Canvas
- 动画
- 代码运行结果

进入这种页面时，把标题、导航、页码全部弱化甚至隐藏。

```text
┌──────────────────────────────────────────┐
│                                          │
│                                          │
│             INTERACTIVE CONTENT          │
│                                          │
│                                          │
│                                   ⛶      │
└──────────────────────────────────────────┘
```

甚至可以增加一个很轻的：

`Explore →`

点击之后，内容进入真正全屏。

这会让整个培训产生一种很明显的“演示模式切换感”。

第三种是「Insight」，用于四象限、框架、数据分析。

不要把四象限做成传统咨询 PPT 那种非常厚重的图表。

更适合这种：

```text
            高投入
               ↑

       02            01
   深度探索         精准执行

低对齐 ←──────────────→ 高对齐

       03            04
   快速试错         自动化

               ↓
            低投入
```

大量留白、极细坐标轴、很少的文字。

鼠标 hover 某个象限时，其他三个象限降低透明度，当前象限轻微放大，同时旁边浮出解释。

这就是 HTML 比 PPT 真正有价值的地方：

**不要把网页做成 PPT，而是把 PPT 内容做成网页。**

第四种是「Canvas / Explore」。

例如你讲 AI Harness、Agent 信息流、组织结构或者复杂概念，可以使用无限画布。

初始页面只展示核心结构：

```text
                 User
                  │
                  ▼
              AI Agent
            ↙     │     ↘
        Memory   Tools   Skills
                  │
                  ▼
               Result
```

点击节点之后展开二级内容。

这样培训体验会比一次性把整张架构图放出来好非常多。

还有一个我认为非常重要的设计：**Progressive Disclosure，渐进式展示。**

你的页面不要一开始把全部信息展示出来。

例如：

```text
AI Agent

01 Understand
02 Plan
03 Act
04 Verify
```

开始只出现：

> AI Agent

点击一下：

> Understand

再点击：

> Plan

再点击：

> Act

这种控制信息出现节奏的方式，会明显增强培训表达效果。

而且你不一定需要传统 PPT 的“下一页”。

整个培训可以有两种导航。

默认情况下：

```text
←        07 / 24        →
```

鼠标移动到底部才出现。

另外按 `M` 可以打开 Overview：

```text
Training

01 Why AI
02 Chat → Agent
03 Harness
04 Context
05 Skills
06 Workflow
07 Demo
08 Practice
```

点击直接跳过去。

我甚至建议取消传统左侧导航栏。

因为在培训过程中，左侧菜单本质上是在持续抢夺注意力。

只有进入“Overview 模式”时才出现完整目录。

页面动画也应该非常克制。

只使用三类动画基本就够了：

`fade`
`slide-up`
`scale`

持续时间保持在大约 200–500ms。

避免：

- 弹跳
- 粒子效果
- 复杂转场
- 卡片飞入
- 大量渐变动画

真正需要视觉冲击的地方应该交给你的视频、3D、Canvas 和互动内容。

还有一个比较重要的东西：**统一 Content Container。**

不管你嵌入什么内容，都使用统一容器：

```text
┌───────────────────────────────────┐
│ Interactive Demo              ↗ ⛶ │
├───────────────────────────────────┤
│                                   │
│                                   │
│              Content              │
│                                   │
│                                   │
└───────────────────────────────────┘
```

视频、iframe、地图、Canvas、图表全部遵循这套规则。

这样即使你的培训内容种类很多，整个系统仍然看起来是一个产品，而不是拼贴网页。

如果让我给你的方案定一个完整方向，我会做成：

**Editorial Minimalism + Interactive Stage**

视觉关键词：

`Warm White`
`Large whitespace`
`Thin borders`
`Typography-first`
`Almost no shadows`
`Monochrome UI`
`One accent color`
`Fullscreen interactive content`

可以参考的视觉关系不是“传统企业培训 PPT”，而更像：

**Apple 发布会的信息层级**
+
**Linear 的 UI 克制**
+
**Notion 的内容感**
+
**Observable / NYT Graphics 的数据互动**
+
**Keynote 的演示节奏**

最终你应该让观众产生一种感觉：

> 这不是一个 PPT，而是一个被设计成“演讲工具”的网页。

而不是：

> 这是一个用 HTML 写出来的 PPT。

如果是我来定义你这套培训的 Design System，我甚至会规定：

**一屏只允许一个主要视觉焦点。**

视频就是视频。

3D 地图就是地图。

四象限就是四象限。

Canvas 就是 Canvas。

不要再给它们周围堆很多标题、解释、标签、导航和按钮。

这会是“简约、干净”最关键的一条。

## M006 · assistant

对，你这个定位应该是“用 HTML 实现的 PPT”，不是“培训网站”。

所以整体设计逻辑要完全切回演示文稿：

每一屏就是一张 16:9 Slide，固定画布，例如 1920×1080。不要顶部导航、侧边栏、搜索框、网页卡片、网站目录这些东西。HTML 只负责承载更强的动态与交互能力，视觉结构仍然必须像一套高级 PPT。

比较适合你的方向是：

**极简演示型 PPT + 沉浸式交互内容**

一页只讲一个核心信息，结构可以控制在几种固定版式：

- 封面页：大标题 + 一张主视觉
- 观点页：一句核心观点 + 极少解释
- 左文右图：左侧结论，右侧视频 / 3D / 图形
- 全屏内容页：视频、3D 地图、Canvas 直接铺满
- 数据页：四象限 / 图表作为唯一视觉中心
- 过程页：节点、箭头、逐步动画
- 章节页：大数字 + 章节名 + 极简背景
- 总结页：3–5 个核心结论

例如四象限页，应该更像：

```text
04 / 08

找到你的发力点

          高收益
             ↑

     探索机会      重点投入

低投入 ───────────── 高投入

       观望        优化效率

             ↓
          低收益
```

而不是做成“网页里的一个四象限组件”。

视频页则可以直接：

```text
02 / 08

ChatGPT 改变的不是搜索，
而是软件的交互模式。


            [ 全屏视频区域 ]


                        → 下一观点
```

3D 地图页面甚至可以只保留左上角一句话：

```text
探索真实世界的数据

通过空间关系，
理解数据背后的真实结构。
```

其余 80%–90% 都交给 3D 地图。

你这套 PPT 最关键的设计原则应该是：

**PPT 决定信息结构，HTML 只负责把 PPT 做到传统 PPT 做不到的程度。**

也就是说：

传统 PPT：
静态图 → 你这里变成交互图  
截图 → 你这里变成真实网页  
视频框 → 你这里变成无缝全屏视频  
流程图 → 你这里变成可展开 Canvas  
地图 → 你这里变成真实 3D 地形  
动画 → 你这里可以根据讲解逐步控制

视觉上我会更建议走：

**Apple Keynote / Linear Launch / Stripe keynote**

而不是 Notion 或 SaaS Dashboard。

## M021 · assistant

你指出的 4 个问题是成立的，而且不是“局部视觉瑕疵”，而是我上一版在方法上就偏了。

第一，复用了原来的图片和流程图，导致“网页重构”实际退化成“旧文章素材重新排版”。这会带来两个问题：一是页面视觉语言不统一，原来的 SVG、截图、文章配图本来是为阅读页设计的，不是为 16:9 演示页设计；二是信息密度和构图逻辑不匹配。文章里的图通常承担“辅助解释”，PPT 里的视觉应该承担“主表达”。直接复用，结果必然像“文章截图搬进 PPT”。

第二，没有真正做内容重构。我上一版实际上做的是“按章节摘要后拆成 18 页”，而不是重新设计课程讲述逻辑。真正的重构应该先回答：这一页讲什么、上一页为什么要引出这一页、这一页观众只需要记住什么、这个观点最适合用视频、动画、3D、四象限、案例还是纯文字表达。现在的页面仍然明显带着文章章节结构，例如“模型看到的为什么远不止你那句话”“工具请求不等于执行”等，虽然内容没错，但更像把 H2 标题变成 Slide 标题，而不是重新设计演讲节奏。

第三，布局系统没有被真正约束住。标题太大和溢出不是某几页偶发，而是 CSS 设计体系的问题。上一版用了大量 `vh` 驱动的字号，例如标题最高到 7.2vh、10vh，再叠加宋体本身较宽、中文标题长度不稳定，结果就是一旦标题达到 16～22 个汉字，很容易超出安全区。并且部分页面用了绝对定位 + 固定 top/bottom 百分比，标题、正文、图形之间没有统一的垂直栅格，所以在 16:9 不同浏览器缩放下很容易互相挤压。核心问题不是“把字号调小”，而是缺少一套严格的 PPT 栅格：标题区高度、正文区起点、内容安全边界、最长标题行数、媒体占比都没有硬约束。

第四，“没有使用正确的文章”这个问题最严重。当前仓库实际上存在几层内容：

`Course/01~07/...md` 是当前七篇正式课程正文；

但第 02 章下面还有：
`大语言模型简要说明/大语言模型简要说明.md`

第 03 章下面还有：
`AI的输入与输出/AI的输入与输出.md`

这两份不是普通附件，它们明显是已经专门为教学讲述、动画和视频准备过的内容。尤其第 03 章的《你只发了一句话，模型实际收到了什么？》，本身就是一条完整的“用户一句话 → 上下文 → 工具请求 → 执行 → 结果回流 → 第二次模型调用”的视频故事线。而我上一版主要以七篇正式文章为主做摘要，只把这些内容当“素材来源”看待，导致实际最适合演讲的内容反而没有成为主线。

第 02 章也是同样的问题。正式文章《AI 的能力从哪里来》已经是经过压缩的解释版，而 `大语言模型简要说明.md` 保留了更完整的 3Blue1Brown 教学故事：脚本缺失回答 → next word prediction → probability → training → parameters → pretraining → RLHF → Transformer → attention。你既然已经做了视频，这部分应该直接围绕视频组织，而不是再做几张抽象的“训练 + 上下文”信息卡片。

因此目前的问题可以归结为：

**我上一版把“课程网站内容”当成了“PPT 内容源”，但没有把它重新变成“演讲脚本”。**

正确的工作顺序应该是：

先盘点所有“最终可讲内容”，区分正式文章、专门教学文章、视频、交互 HTML、案例和原始素材；

然后重建一条课程故事线；

再决定每一个观点最适合哪种媒介；

最后才设计页面。

而不是先定 18 页，再往每一页塞现成内容。

从当前仓库看，我认为课程真正应该围绕这几类核心资产组织：

- 第 02 章的视频 / LLM 原理内容：负责回答“AI 到底是什么、能力从哪里来”
- 第 03 章的视频：负责回答“一次对话背后实际发生了什么”
- 第 04 章思维地形 HTML：负责回答“为什么需求会漂移、纠缠，以及怎么通过反馈收敛”
- 第 06 章四象限 HTML：负责回答“什么时候该继续投入，什么时候应该先探索”
- 其他文章中的案例和方法论：用于把这些机制落回实际工作

所以真正的课程主线更可能是：

**为什么 AI 看起来很聪明，却仍然经常不好用**
→ **它本质上在做什么**
→ **一次真实任务背后发生了什么**
→ **人与 AI 为什么会逐渐偏离**
→ **怎么反馈和对齐**
→ **什么时候值得继续投入**
→ **最终人负责什么**

这比现在简单地按 01～07 章节顺序搬过去，更适合培训。

视觉上也应该重新定一条硬规则：

**禁止直接把现有文章配图作为 Slide 主视觉。**

旧素材可以作为事实参考、视觉参考或内容来源，但 PPT 页面应该重新绘制为演示级构图。唯一例外是视频和真正的交互 HTML，因为它们本身就是演示媒介。

所以你看到的“复用图片、没有重构、标题溢出、文章不对”，其实是同一个根因：**上一版仍然是在“把现有网站改成 PPT”，而不是“重新设计一门课程，再用 HTML 去实现 PPT”。**
