你说的应该是 **Transformer**。这类大语言模型通常采用 Transformer 架构，同时用深度学习方法训练，两者不冲突：

- **Transformer**：模型采用什么结构。
- **深度学习**：通过多层神经网络学习的方法。
- **预训练、后训练**：在不同目标和材料下进行训练的阶段。

上一版只写“多层计算”，没有交代 Transformer，确实让模型显得过于笼统。这需要先改教学设计，再改动画。

建议保留五阶段，但让“同一个 Transformer 模型如何被训练”成为后半段的主线：

| 阶段 | 设计调整 |
|---|---|
| 什么是数据 | 保留五类数据与窗边猫案例，建立“现实对象—不同记录”的关系。 |
| 数据处理 | 演示筛选、清理、组织，再沿文字路径拆分 Token、转换表示。明确这些步骤准备的是输入。 |
| 预训练 | **先介绍已存在的 Transformer 模型**，用一处局部动画展示：当前位置如何关联前文、经过多层计算，得到下一 Token 的预测。随后拉回全景，演示原文目标、比较、反馈与参数更新。 |
| 后训练 | 保留同一个 Transformer 对象，改变训练材料和目标，展示任务示范与反馈如何进一步调整行为。 |
| 模型形成 | 收束为“Transformer 结构 + 训练得到的参数”，回顾待训练、基础模型、后训练模型三种状态。 |

这里最需要分清两条过程：**一次预测中的前向计算**，以及**多次训练中的参数更新**。前者解释 Transformer 怎样处理输入，后者解释数据怎样改变模型。不能把经过多层计算画成完成了多轮训练。

我建议先修改分镜，优先解决这三个问题：Transformer 首次怎样出现、内部计算讲到什么深度、内部局部动画怎样接回训练回路。“深度学习”保留为一句方法说明，不必承担主要画面解释。喵～

**没有哪条要求规定整片必须用文字和方块。** 原分镜甚至明确写了：“只看见猫、Token、箭头和 QA 卡片，却答不出它们之间的关系，不能算完成。”文字密度和全景／局部比例也仍待确认。问题来自我后续的设计选择：把数据、模型、预测差距、调整方向都装进了相似的容器，再通过箭头串联。这样容易检查“概念有没有出现”，却难以判断“机制有没有被看懂”。[原分镜](</Users/w/code/For-Use-AI/课程材料/AI机制与有效使用/02-数据生成与模型训练全过程/独立视频分镜.md>)

此前使用了 Manim，但 **Manim 只负责把设计变成动画，无法替代解释设计**。我对 3Blue1Brown 的借鉴停留在局部运动和对象对应关系，没有贯彻到整段叙事。

你给的截图恰好能说明这个差别。我核对到了官方源码中的 `InformationOfLanguage` 场景：

- 每个字母下面的绿色圆，表示模型预测这个字母的概率。
- 上面的蓝柱表示：这个字母出现时，带来了多少信息。越难预料，柱子越高。
- 随后，竖直的柱子旋转并首尾拼接，形成上方的长条，让观众看到整句话的信息量如何累加。
- 公式表达的是观众已经从这些变化中看到的关系。

**这张图是一个逐步推导的结果。** 字母格子有位置含义，圆的面积、柱的高度和长条的长度都有数量含义。它们共同描述同一件事，所以画面虽然复杂，仍有清楚的对应关系。[对应源码](https://github.com/3b1b/videos/blob/4dd996dd4fdddef717273e65c97f2227c31493ac/_2026/cross_entropy/entropy.py#L1873)

对于模型训练，更直接的参考是他们的 `LossFunction` 场景：目标词的预测概率、对应的差距柱、整体平均值会联动变化。观众先看到“模型越能预料原文，整体差距越小”，再理解指标的名字。[对应源码](https://github.com/3b1b/videos/blob/4dd996dd4fdddef717273e65c97f2227c31493ac/_2026/cross_entropy/language_models.py#L803)

因此，我认为需要从三个方面调整。

**第一，围绕一个持续变化的例子组织画面。**

预训练的核心段落，可以一直保留“这只猫坐在……”这个例子：

1. 模型给出几个可能的续写，用长度直接显示它更倾向哪个词。
2. 揭开原文中的下一个词，例如“窗边”，让观众看到模型原先对它的预期有多低。
3. 放大模型内部的一处可调数值，轻微改变它，观察目标词的预测倾向随之变化。
4. 展示怎样计算出有助于缩小差距的调整方向，再进行一次小幅调整。前面的轻微改变只是帮助理解影响关系，不能暗示实际训练逐个试旋钮。
5. 回到预测画面，让观众看到这次调整的作用；再加入其他例子，说明一次更新需要综合多个例子的反馈。

这样，“学习”有了可见的前后关系。现在版本里的彩色小块变色，并没有交代这些变化究竟改变了什么。

**第二，先让观众理解作用，再决定是否出现术语。**

| 原术语 | 画面上优先使用的文字 | 动画需要证明的含义 |
|---|---|---|
| 损失 | 预测差距 | 模型越不看好原文答案，这项差距越大 |
| 梯度 | 调整方向 | 哪些数值应该往哪个方向改变、影响有多大 |
| 参数 | 模型中的可调数值 | 改变这些数值，会改变模型的计算和预测 |

这些是教学用的简化表达。“预测差距”需要通过概率变化讲清楚，避免被理解成字数差异；“调整方向”也不能画成答案直接流回模型。**只替换框里的词，仍然解决不了问题。**

**第三，保留预训练、后训练，但让阶段差异发生在同一套视觉机制里。**

预训练展示“从大量原文学习预测”；后训练沿用同一个模型，换成示范回答、回答偏好等训练信号，展示它如何进一步调整回答方式。这样可以自然说明：Transformer 是模型架构，深度学习贯穿这些训练阶段。

画面文字则只保留章节名、例子、必要对象名和当前结论。“此处不代表真实规模”“不保证效果”等反复出现的制作备注应移出主画面；影响理解的简化条件集中交代一次。

我的回顾结论是：**下一版应先确定每个图形代表什么、它的变化能让观众推断出什么，再安排文字和镜头。** 如果隐藏解释字幕后，只剩下盒子移动和箭头闪烁，这一段就还没有设计完成。我们先把“一次预测怎样带来一次学习”讨论透，再据此重新组织整片。喵～
