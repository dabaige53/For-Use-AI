```markdown
# Issue tracker: Local Markdown

本仓库的任务、规格和决策保存在本地 Markdown 文件中，使用本地 Git 管理版本。发布到任务跟踪器指写入本地文件；同步到外部平台需用户另行明确要求。

## 文件约定

- 每个功能一个目录：`.scratch/<feature-slug>/`。
- 规格：`.scratch/<feature-slug>/spec.md`。
- 实现任务：`.scratch/<feature-slug>/issues/<NN>-<slug>.md`，从 01 编号，每票独立文件。
- 普通任务的分类状态写在文件顶部的 `Status:`，取值见 `triage-labels.md`。
- 讨论记录追加在文件底部的 `## Comments` 下。
- 获取任务时读取用户指定的文件；仅提供编号时，先确定所属功能目录。

## Wayfinder

Wayfinder 使用独立的执行状态，保留现有任务格式。

- 地图：`.scratch/<effort>/map.md`，记录目标、说明、已决事项和待解决问题。
- 子任务：`.scratch/<effort>/issues/<NN>-<slug>.md`。
- `Type:` 为 research、prototype、grilling 或 task。
- `Status:` 为 open、claimed 或 resolved。
- `Assignee:` 记录领取人。
- `Blocked by:` 记录依赖任务编号；无依赖时为 none。
- 选择任务时，按编号取首个状态为 open 且所有依赖均已 resolved 的任务。
- 开始工作前保存 `Status: claimed` 和领取人。
- 完成时追加 `## Answer`，设为 resolved，并将结论摘要和文件链接追加到地图的已决事项中。
- 如需额外记录 triage 分类，使用 `Triage:` 字段，保留 `Status:` 的执行状态含义。
```
